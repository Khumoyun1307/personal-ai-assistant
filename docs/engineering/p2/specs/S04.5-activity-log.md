## 1. Goal

The owner can see everything the assistant did on their behalf: `/activity` in the control chat and the `get_activity` tool ("what did you send today?") list sent messages, drafts (awaiting, rejected, expired, outdated, cancelled), blocked, failed and uncertain sends — each with the contact, the time, a short excerpt and who authorised it. Sent messages and drafts look clearly different. A catch-up (`summarize_period`) also lists what the assistant sent or drafted in that period.

## 2. Scope

**In:** a read model over `actions` and `audit_log`; the `/activity` command; the `get_activity` read tool; a deterministic "assistant activity" block in `summarize_period`'s result.

**Out:** anything that changes an action; prompts (the `owner_request` rule that tells the model to use `get_activity` is written by Viro in S04.3 — you put the rule text in your PR description); a bot command menu (the product has no `setMyCommands` call and P2 adds none). **In:** exactly one line for `/activity` in the `/help` text (decisions R12, §5 step 7).

## 5. Step-by-step

Run every check inside the container with your compose project (`$env:COMPOSE_PROJECT_NAME='junior'`).

1. **Read first.** `agent/tools/summaries.py` (how a read tool is built: args model with validators, `ToolDefinition`, `ToolOutcome` with `refs` and `untrusted`, `name(...)` wrapping, `local_time`), `agent/tools/common.py` (`require_contacts`, `require_conversations`, `local_time`, `parse_local_moment`), `agent/untrusted.py` (`wrap`, `Source`), `actions/states.py` (labels, reasons — from F0), `tests/integration/p2_factories.py`. *Check:* you can name the function each later step will call.

2. **Read model** — `actions/activity.py`:
   ```python
   @dataclass(frozen=True, slots=True)
   class Authorization:   # who allowed it to be sent
       kind: Literal["owner_approval"]          # "delegation" arrives in M06
       approved_at: datetime; version: int
   @dataclass(frozen=True, slots=True)
   class ActivityEntry:
       action_id: int; conversation_id: int; contact_id: int
       contact_display_name: str | None; contact_username: str | None
       origin: str; state: str; state_reason: str | None; group: str     # see below
       created_at: datetime; decided_at: datetime | None; executed_at: datetime | None
       version: int; excerpt: str | None                                  # first 120 chars of actions.text, or None if purged
       authorization: Authorization | None
       deleted_in_chat_at: datetime | None   # the sent message was later deleted in the chat (owner E2, below)
   async def activity(session, *, account_id: int, since: datetime, until: datetime,
                      conversation_ids: Sequence[int] | None = None, groups: Sequence[str] | None = None,
                      limit: int = 50) -> list[ActivityEntry]
   ```
   - Every query filters `account_id` (RG-21). Order by the entry's time (`executed_at` or `decided_at` or `created_at`), oldest first.
   - `group` ∈ `sent` (succeeded), `uncertain` (delivery_uncertain), `failed` (failed), `awaiting` (awaiting_approval, revising, approved, executing), `not_sent` (rejected, outdated, expired, cancelled), `blocked` (blocked).
   - `deleted_in_chat_at` (owner decision E2, 2026-10-26: every deletion is noted and shown in reports and summaries): for `sent` entries, `messages.deleted_at` of the `assistant_sent` row whose `action_id` is this action (NULL when not deleted). Telegram does not say who deleted it (TF §12 LV-07), so the entry never says who.
   - `authorization`: for `sent`/`uncertain`/`failed`, the latest `audit_log` row with `event = 'action_approved'`, `subject_type = 'action'` and `subject_id = action_id` (its `at` and `details.version` — the event and details shape of F0-interfaces §11 / S04.1 §3.6). None otherwise.
   *Check:* `just test tests/integration/test_activity.py -k read_model` passes the read-model tests from §6.

3. **Rendering** — in `telegram/control/activity.py`, a pure function `render_activity(entries, *, timezone, period_label) -> str`: one line block per entry: local time, contact name (escaped with `telegram/render.escape`), a **group label that makes drafts and sent messages different** (use `actions/states.py`'s owner labels: e.g. "✓ Sent 18:05", "📝 Draft — awaiting your approval", "✗ Not sent — <reason>", "⚠ Delivery uncertain — please check the chat"), the excerpt (escaped, in quotes), and for sent ones "approved by you at 18:04 (version 2)"; a sent entry with `deleted_in_chat_at` adds "— deleted in the chat at 18:20 (Telegram does not say by whom)". Empty period: "Nothing was sent or drafted <period>." At most 30 entries; if more, add "…and N more — ask me for a narrower period." *Check:* `just test tests/unit/test_activity_render.py`.

4. **`/activity` command** — `handle_activity(session, gateway, clock, scheduler, account, message, argument)` matching F0's `CommandHandler`: argument `today` (default), `yesterday` or `7d`, computed in the owner's timezone (`account.timezone`); anything else ⇒ a one-line usage reply. Sends with `gateway.send_text(ControlChat(...))` — never `Message.answer()`. Register it in `_wire_m04` as `commands["activity"]`. Logs: counts only. *Check:* `just test tests/integration/test_activity.py -k command`.

5. **`get_activity` tool** — `agent/tools/activity.py`:
   - Args (strict, validators not schema keywords — copy `SummarizePeriodArgs`'s style): `since: str | None`, `until: str | None` (owner-local `YYYY-MM-DD HH:MM` or `YYYY-MM-DD`; default today 00:00 → now; at most 31 days), `conversation_id: int | None`, `contact_id: int | None` (at most one of the two), `show: Literal["all", "sent", "drafts", "problems"]` (default `all`; `drafts` = awaiting + not_sent; `problems` = failed + uncertain + blocked), `limit: int` 1–50 (default 30).
   - Check a given contact/conversation with `require_contacts`/`require_conversations` (a foreign id ⇒ `LookupError` ⇒ the executor answers "not found").
   - Result data: `{"period": {...}, "entries": [{"action_id", "conversation_id", "contact_id", "contact_name": wrap(name, Source.CONTACT_NAME), "group", "state_reason", "time": local, "excerpt": wrap(excerpt, Source.OWNER_IN_BUSINESS_CHAT), "authorized": {"approved_at": local, "version"} | null}], "count", "status_rule": "Report each entry's group exactly; never call a draft or an uncertain send 'sent'."}`.
   - `ToolDefinition(name="get_activity", capability=READ, release_flag="tool.get_activity", returns_managed=True, ...)`; the outcome sets `contains_managed=True`, `untrusted=True` (names and excerpts taint the run) and `refs` = every conversation and contact listed.
   - Register in `default_registry()` (one import, one entry). Then add `"get_activity"` to the expected managed-tool set in `tests/unit/test_tool_registry.py` (the only change allowed there). *Check:* `just test tests/integration/test_activity.py -k tool tests/unit/test_tool_registry.py`.

In `agent/tools/summaries.py`, a private helper `_assistant_activity_entries(...)` turns it into `[{"conversation_id", "contact_id", "contact_name": wrapped, "sent", "awaiting", "not_sent", "problems", "deleted_after_send"}]`, and `summarize_period_tool` adds it as `"assistant_activity"` (an empty list when nothing happened). *Check:* `just test tests/integration/test_catch_up_activity.py`.
