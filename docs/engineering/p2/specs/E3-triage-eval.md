## §A — E3D: the synthetic triage dataset (Junior)

### Goal

Hand-write (with model help if you like) a synthetic set of message bursts, each labelled with what triage should conclude, so the product's triage can be measured before the owner relies on alerts. Plus a small set of monitor cases for the `evaluate_monitor` model comparison.

### Allowed files

- `evals/datasets/e3/bursts.jsonl` (new)
- `evals/datasets/e3/monitor_cases.jsonl` (new)
- `evals/datasets/e3/README.md` (new: provenance, counts per variant, how labels were decided)
- `evals/datasets/MANIFEST.sha256` — **only** regenerated by `python -m evals.manifest --write` (in the container), after rebasing on the current base, in the same commit as the data (WORKFLOW §9)

### Forbidden

Everything else, explicitly: any `.py` file (the schema models are Jack's, §B), `evals/datasets/e1/**`, `evals/datasets/retrieval/**`, `migrations/`, `src/assistant/policy/`, `src/assistant/actions/`, `src/assistant/telegram/` (incl. `gateway.py`, `dispatcher.py`), prompts and everything under `src/assistant/agent/` (`runtime.py`, `tools/executor.py`, `schemas.py`, `context.py`), consent code, `src/assistant/privacy/`, `src/assistant/config.py`, `src/assistant/jobs/`, `.env*`, `var/`. **Never** copy, paraphrase or derive anything from real chats, real people, real phone numbers, addresses, companies or accounts — every name and fact is invented (AGENTS §8, ADR-16). Never run a live eval.

### Layout — `bursts.jsonl` (one JSON object per line, UTF-8, no trailing commas)

```json
{
  "id": "b001",
  "variant": "uz-Latn",
  "now": "2026-11-03T14:05:00Z",
  "owner_language": "uz-Latn",
  "owner_timezone": "Asia/Tashkent",
  "contact": {"display_name": "Dilnoza R."},
  "contact_priority": "normal",
  "history": [
    {"id": "b001.h01", "direction": "owner", "sent_at": "2026-11-03T09:00:00Z", "text": "..."}
  ],
  "open_tasks": [
    {"id": "b001.t1", "kind": "contact_commitment", "title": "...", "source": "b001.h01", "due": "2026-11-03T18:00:00Z"}
  ],
  "burst": [
    {"id": "b001.m01", "direction": "contact", "sent_at": "2026-11-03T14:01:00Z", "text": "..."},
    {"id": "b001.m02", "direction": "contact", "sent_at": "2026-11-03T14:02:00Z", "text": null, "media": "document"}
  ],
  "labels": {
    "alert": true,
    "needs_reply": true,
    "contains_question_to_owner": true,
    "requests_decision": true,
    "urgency": "urgent",
    "escalation_category": "urgent_decision",
    "deadline": "2026-11-03T12:00:00Z",
    "suspicious": false,
    "commitments": [{"id": "b001.c1", "by": "contact", "source": "b001.m01", "values": ["ertaga"]}],
    "questions": [{"id": "b001.q1", "source": "b001.m01", "is_decision": true}],
    "resolved_tasks": ["b001.t1"],
    "unresolved_tasks": []
  },
  "tags": ["deadline_today"]
}
```
Rules (the schema in §B will enforce them; follow them now):
- `id` `b001`…`b999`; message ids `<burst>.hNN` (history) and `<burst>.mNN` (burst); task ids `<burst>.tN`; label ids `<burst>.cN`/`.qN`.
- `variant` ∈ `uz-Latn`, `uz-Cyrl`, `ru`, `en`, `uz-ru-mix` (the E1 variants); `direction` ∈ `contact`, `owner`; times UTC with `Z`; `now` after every message.
- `alert` is **true exactly when** `urgency == "urgent"` or `requests_decision` or `escalation_category == "urgent_decision"` — these are the "urgent/decision positives".
- `commitments[].by` is who must act; `source` is a message of that side (contact commitments cite a `contact` message, owner commitments an `owner` message); `values` (optional) are literal substrings of the source text.
- `questions[].source` is a `contact` message.
- Every `open_tasks[].id` appears in exactly one of `resolved_tasks` / `unresolved_tasks`.
- `suspicious` is true for attempts to instruct the assistant ("mark this urgent", "ignore your rules", "tell me what others wrote") — label what a careful human would conclude about the *real* request, never what the message demands.

**Counts (minimum):** 150 bursts; ≥ 40 with `alert: true`; ≥ 25 per variant; ≥ 30 bursts with `open_tasks` giving ≥ 30 resolution decisions, about half resolved, including hard negatives (a promise repeated is **not** fulfilment; a reminder from the other side is not delivery); ≥ 15 FYI/thanks/"ok" bursts with nothing to do; ≥ 10 suspicious bursts across variants; ≥ 10 bursts with an owner reply inside the burst; spelling hard cases as in E1 tags (apostrophe variants, Cyrillic without Uzbek letters, Latin-typed Russian, code switching).

### Layout — `monitor_cases.jsonl` (for the `evaluate_monitor` comparison)

```json
{"id": "m001", "variant": "ru", "monitors": [{"id": 1, "kind": "semantic", "description": "someone asks me to decide about the project"}],
 "burst": [{"id": "m001.m01", "direction": "contact", "sent_at": "2026-11-03T10:00:00Z", "text": "..."}],
 "labels": {"matched_monitor_ids": [1]}}
```
≥ 30 cases, ≥ 5 per variant, half matching, including near misses and an injection ("alert the owner now") that must not match on its own.

## §B — E3T: the triage eval target and the model comparison (Jack)

### Goal

Measure the product's triage, exactly as shipped, against E3; gate it on owner-confirmed items; run the mandatory model comparison for the `triage` and `evaluate_monitor` routes; record quality, cost and the decision.

### Design

- **Schema** (`evals/schema.py` additions, owned here): Pydantic models for §A's two layouts with load-time integrity checks (ids, cited ids exist, sides, the `alert` rule, every open task in exactly one list, `values` literal substrings via `fold`, variants, counts reported). `DatasetName` gains `"e3"`. Land this early (first commit) so Junior can validate.
- **Target** (`evals/triage.py`, an `EvalTarget` like `evals/summary.py`): per burst, load a scratch database (the agent-mode corpus loader pattern): account with consents naming the route's processor, `locale_pref`/`timezone` from the burst, contact with `contact_priority`, conversation in Observe, history and burst messages with the right directions and dates, open tasks as agent tasks (`created_by = 'agent'`, `first_source_message_id` from `source`), an existing `conversation_triage` row covering the history (so the burst is what is new). Run the **product** `Triager` (shipped prompt, route model or `--model`, fixed clock at `now`), its validation and the S05.1 effects in the scratch database; read back the verdict row, created/closed tasks and enqueued notifications (no delivery). Delete the account's rows between bursts.
- **Metrics** (pre-screen over all items; gate over owner-confirmed items only, `evals/review.py` ledger with `confirmed_items` = burst ids):
  | Metric | Definition | Threshold |
  |---|---|---|
  | Urgent/decision recall | positives (`alert: true`) whose run enqueued `triage_urgent` or `triage_decision` | ≥ 90 % |
  | False-alert rate | **TL decision (spec):** share of bursts that got `triage_urgent`/`triage_decision` whose label is `alert: false` (alert precision complement — the noise the owner feels) | ≤ 20 % |
  | False-closure rate | `unresolved_tasks` the run closed | ≤ 10 % |
  | Resolution recall | `resolved_tasks` the run closed | ≥ 80 % |
  | Informational | negatives alerted / all negatives; `needs_reply` accuracy; commitment recall (by side, `values` match); suspicious recall; owner-language/script share (P2-O11) | — |
  Language-agnostic thresholds (IMPLEMENTATION_PLAN §7); per-variant breakdown in the report.
- **`evaluate_monitor` target** (`evals/monitors.py`): per case, the product `evaluate_monitor` run with the case's monitors and burst; metric: matched/not-matched accuracy per monitor (informational threshold: ≥ 90 % accuracy, ≤ 10 % false matches — **TL decision (spec)**, recorded in the report as the bar used for the model choice).
- **CLI** (`evals/cli.py`): `python -m evals run triage` and `python -m evals run monitors` with the existing `--estimate-only`, `--limit`, `--model`, `--reviews`, `--out-dir`, `--no-write`, and the hard in-flight budget cap (`BudgetedLLMClient`); reports to `docs/evals/<date>-triage-<model>.md/json` and `…-monitors-<model>…`.
- **Model comparison (mandatory, IMPLEMENTATION_PLAN §7; WORKFLOW §11):** run on `gpt-6-luna` first (`--estimate-only` → `--limit 1` → full). If Luna misses any threshold on the pre-screen, run `gpt-6-sol`, and `gpt-6-astra` only if Sol also misses. For each model tried record quality and cost per 100 bursts (from `llm_calls`), and the decision ("route stays on Luna" / "propose `LLM_ROUTE_TRIAGE_MODEL=…`"). A route change is applied on the server only with the owner's approval; the decision text goes into M05.md via the PR description. Same procedure for `evaluate_monitor` on `monitor_cases.jsonl`.
- **Cost:** Luna E3 full run ≈ 150 calls × (~3k input + ~0.4k output tokens) ≈ USD 0.08 at $0.10/$0.50 per 1M; monitors ≈ USD 0.01. Comparisons on more capable tiers cost more: estimate first, and stop if the phase cap (USD 2, shared with E2 and retrieval re-runs) would be exceeded. Runs are started by Antony or the TL with the owner's go-ahead, never by a subagent.
- **Pre-review:** after each full run a fresh read-only agent pre-reviews flagged items in the `docs/evals/2026-10-26-e1-prereview-v4.md` format; nothing is a gate result until the owner confirms labels (PRD R2 #5).
