## 1. Goal

The application, not the model, decides whether an owner-voice action may exist and may be sent (AGENTS §6 invariant 1, D-06). This unit delivers the pure policy engine (`decide`), the loader that builds its input from locked rows, the proposal service every draft and dictated message goes through, and the single-action state transitions the approval UX (S04.3) and the executor (S04.4) call. Nothing here talks to Telegram or a model.

## 2. Scope

**In:** `policy/rules.py`, `policy/engine.py` (`decide`), `policy/explanations.py`; `actions/policy_loader.py`; `actions/proposals.py` (`propose`); single-action transitions in `actions/lifecycle.py` (beside F0's bulk helpers); the `ingestion_state` reader and its `system_state` key names (S04.4 writes the keys); table-driven rule tests; the hypothesis state-machine test.

**Out:** sending, Tx A/Tx B, `mark_uncertain`, barrier writing, kill switch, call sites in connections/consent (S04.4); the mode call site (`conversations/modes.py`, S04.2 — decisions R12); cards and callbacks (S04.3); drafting and the ingestion listener (S04.2); autonomy rules beyond the two P2 needs (M06).

## 3. Design

### 3.1 Rules (`policy/rules.py`)

Each rule is a pure function `(ctx: PolicyContext) -> CheckResult | None`; `None` means "not applicable to this phase or kind" and the rule is left out of `Decision.checks`. Rule order below is the evaluation and reporting order. All reason strings are codes (no free text).

| # | Rule | Phases | Applies to | Passes when | Reason codes on failure |
|---|---|---|---|---|---|

| 2 | `connection_active` | both | all | `connection.exists` and `status == "active"` and `is_enabled` and `can_reply` | `no_connection`, `connection_disabled` (not enabled or status `disabled`), `connection_stale` (status `stale`), `no_reply_right` |
| 3 | `conversation_owned` | both | all | `conversation.account_id == account.account_id` and not `is_bot` | `not_owned`, `bot_chat` |
| 4 | `conversation_available` | both | all | `mode != "ignore"` and (`availability != "possibly_paused"` or `action.owner_retry`) | `chat_ignored`, `chat_possibly_paused` |
| 5 | `window_open` | both | `delegation_auto` only (owner decision 2026-10-30, P2-O20) | `core.reply_window.is_open(conversation.last_contact_msg_at, now)` (24 h − 5 min, contact messages only). Owner-dictated and owner-approved actions: not applied — Telegram enforces the window at the one send attempt | `window_closed` |
| 6 | `no_takeover_since` | both | all | `freshness.newest_owner_manual_sent_at is None` or `≤ ref`, where `ref = freshness.base_message_sent_at` when it is set, else `action.created_at`. ### 3.2 `decide` (`policy/engine.py`)

```python
def decide(ctx: PolicyContext) -> Decision:
    checks = tuple(c for rule in RULES if (c := rule(ctx)) is not None)
    failed = [c for c in checks if not c.passed]
    if ctx.phase is Phase.PROPOSAL:
        outcome = Outcome.DENY if failed else Outcome.REQUIRE_APPROVAL  # never ALLOW_AUTO in P2
    elif not failed:
        outcome = Outcome.ALLOW_AUTO  # see note
    elif all(c.name == "inbox_drained" for c in failed):
        outcome = Outcome.WAIT
    else:
        outcome = Outcome.DENY
    return Decision(outcome, checks)
```
- **Execution-phase `ALLOW_AUTO` means "may send now"** for every origin: an owner-approved action already carries its approval, and Tx A only asks whether sending is still allowed. `REQUIRE_APPROVAL` is a proposal-phase outcome only. **TL decision (spec)** — F0-interfaces §3 does not say this explicitly; record it in ARCHITECTURE §9.2 as built.
- `WAIT` only when `inbox_drained` is the sole failure; any other failure denies (a pending update cannot make a failed check pass, and not sending is always safe).
- `decide` is total: for any `PolicyContext` built from valid enum values it returns a `Decision` and never raises; it reads no clock, no environment, no globals.

**Execution failure → state** (consumed by S04.4; the first matching row wins): `already_claimed` → no change; `takeover` → `outdated`/`takeover`; `new_contact_message` → `outdated`/`new_contact_message`; `source_deleted` → `outdated`/`source_deleted`; `window_closed` → `expired`/`window_closed`; `max_age` → `expired`/`max_age`; `consent_missing` → `blocked`/`consent_revoked`; `sending_disabled` → `blocked`/`sending_disabled`; `too_long`/`empty_text` → `blocked`/`too_long`; `autonomy_paused` → `cancelled`/`autonomy_paused` (autonomous origin only); any other → `blocked`/`policy_denied`. The full `Decision` is stored in `actions.policy_decision` (F0-schema §2.1) either way. Provide this mapping as `policy.engine.execution_target(decision) -> tuple[ActionState, StateReason] | None` so S04.4 does not re-implement it.

### 3.3 Explanations (`policy/explanations.py`, FR-ACT-03)

`EXPLANATIONS: Mapping[str, str]` — one plain English sentence per reason code, saying what happened and what the owner can do, never quoting message text or names (e.g. `window_closed`: "Telegram's 24-hour reply window for this chat has closed, so a reply cannot be sent. Copy the text and send it yourself if you still want to."; `no_reply_right`: "Alviro is connected without the right to reply in your chats. Turn on "Reply to messages" in Telegram's Chat Automation settings, or copy the text and send it yourself."; `takeover`: "You replied in this chat yourself after this draft was made."). `explain(decision) -> tuple[str, ...]` returns the sentences of the failed checks in order. English only in P2 (P2-O11), one table, easy to extend with locales later.

### 3.4 Loader (`actions/policy_loader.py`)

```python
async def load_context(session, *, account_id: int, conversation_id: int, facts: ActionFacts,
                       base_message_id: int | None, target_message_id: int | None, owner_requested: bool,
                       phase: Phase, now: datetime, config: ActionsConfig, ai_generated: bool,
                       process_run_id: str | None) -> PolicyContext
```
`owner_requested` = origin `owner_dictated` or the action has a `trigger_turn_id` (decisions R3). `process_run_id` is the caller's own process run id (F0 generates it in `bootstrap.running_process` and injects it into the executor); `None` outside a running process (proposals, tests that do not exercise the barrier) — the barrier is only evaluated at execution.
Precondition: the caller holds the §9.4 locks (account `FOR SHARE`, conversation `FOR SHARE` or `FOR UPDATE`, the action `FOR UPDATE` when it exists). All reads are account-scoped; a conversation not in the account raises `core/errors.py::NotInAccountError` (the caller reports "not found", AGENTS §6.12; ARCHITECTURE §8.3).

| Field | Source |
|---|---|
| `account.status`, `autonomy_paused` | `accounts` row |
| `account.managed_consent_ok` | `accounts.service.active_consent(ai_managed)` granted **and** naming `core.model_routes.processor_for_model(<draft_reply route model>)` (the route model comes from `ActionsConfig`) |
| `connection.*` | the account's `business_connections` row; `can_reply` = `capability_tier(is_enabled, rights) in {CAN_REPLY, EXTENDED}` (`accounts/connections.py`) |
| `conversation.*` | `conversations` row; `is_bot` from its `contacts` row |
| `freshness.newest_owner_manual_sent_at` | `max(messages.sent_at)` where `direction = 'owner_manual'` in this conversation, tombstones included (an owner message the owner later deleted still means the owner acted) |
| `freshness.newest_contact_message_id` | `max(messages.id)` where `direction = 'contact'` in this conversation, tombstones included |
| `freshness.base_message_sent_at` | the base row's `sent_at` **only when not `owner_requested`**; `None` otherwise (the takeover reference is then `created_at`, rule 6) |
| `freshness.base_message_present` | present = no base, or the base row exists with `deleted_at` and `purged_at` both NULL (computed for every action) |
| `freshness.target_is_assistant_sent` | edit/delete only: the target row exists in the same conversation, `direction = 'assistant_sent'`, not deleted; else `None` |
| `ingestion` | `ingestion_state(session, process_run_id=process_run_id)` below |
| `sending_enabled` | `ActionsConfig.sending_enabled` (flag `actions.send`) |

`ingestion_state(session, *, process_run_id: str | None) -> IngestionState`: `pending_inbound` = count of `inbound_updates` with `status = 'pending'` (any account: a pending row has no account yet, ARCHITECTURE §9.3 personal phase); `barrier_passed` from `system_state` key `KEY_INGESTION_BARRIER = "ingestion_barrier"` with value `{"process_run_id": str, "caught_up_at": iso | null}` — **bound to the process run** (decisions R1): passed **only** when the stored `process_run_id` equals the caller's own `process_run_id` **and** `caught_up_at` is set. Anything else is not passed (fail closed): a missing key (restored scratch database), a key left by a previous run (the new run commits its reset before any role starts, F0), a `None` caller run id, or a process started without the poller role (its run id is never caught up; R4 changes this). F0 writes the reset; S04.4's poller sets `caught_up_at`; define the key name and the reader here.

### 3.5 Proposals (`actions/proposals.py`, F0 signature)

```python
async def propose(session, request: ProposalRequest, *, clock: Clock, config: ActionsConfig) -> ProposalResult:
    now = clock.now()
    if request.origin is ActionOrigin.DELEGATION_AUTO:      raise ProposalRefused("autonomous_not_available")   # P2
    if request.kind is not ActionKind.SEND_MESSAGE:          raise ProposalRefused("kind_not_proposable")       # RG-12 mechanics only
    # 1. Idempotency on the model's call.
    if request.run_id is not None and request.tool_call_id is not None:
        if (existing := await _by_call(session, request)) is not None:
            return _result(existing, reused=True)
    # 2. Locks, §9.4 order. Account-scoped; NotInAccountError if the conversation is not the account's.
    await _lock_account_share(session, request.account_id)
    conversation = await _lock_conversation_update(session, request.account_id, request.conversation_id)
    # 3. A retried owner turn reuses its live action instead of superseding it (§8.3 step 4).
    if request.trigger_turn_id is not None:
        if (live := await _live_for_turn(session, request)) is not None:
            return _result(live, reused=True)
    # 4. Facts and the proposal-phase decision.
    shown_through = request.shown_through_message_id or await _newest_contact_id(session, conversation.id)
    expires_at = _expiry(now, conversation.last_contact_msg_at, config.approval_max_age)
    facts = ActionFacts(None, request.kind, request.origin, ActionState.PROPOSED, 1,
                        utf16_len(request.text), now, expires_at, shown_through, owner_retry=False)
    owner_requested = request.origin is OWNER_DICTATED or request.trigger_turn_id is not None   # decisions R3
    ctx = await load_context(session, ..., owner_requested=owner_requested, phase=Phase.PROPOSAL,
                             ai_generated=request.origin is AGENT_PROPOSAL, process_run_id=None)
    decision = decide(ctx)
    # 5. Insert as `proposed` (outside the live-card index), ON CONFLICT (run_id, tool_call_id) DO NOTHING;
    #    on conflict load the existing row and return it as reused. Stores `request.draft_flags` in
    #    `actions.draft_flags` (decisions R8; non-content) and `base_message_id` (NULL for owner_dictated).
    action = await _insert(session, request, facts, decision)
    if decision.outcome is Outcome.REQUIRE_APPROVAL:
        superseded = await _supersede_live(session, conversation.id, now)   # FOR UPDATE; awaiting|revising → outdated/superseded
        await _transition(action, PROPOSED → AWAITING_APPROVAL, approval_token=new_token(), expires_at=expires_at)
    else:  # DENY
        superseded = None                                                     # a blocked proposal never supersedes (TL decision (spec))
        await _transition(action, PROPOSED → BLOCKED, reason=_blocked_reason(decision))
    return ProposalResult(action.id, action.state, reused=False, superseded_action_id=superseded, decision=decision)
```
- `ProposalRequest` (F0) carries `draft_flags: Mapping[str, Any] | None` (decisions R8): the non-content `DraftResult` flags (`needs_reply`, `confidence`, `sensitive_topic`, `makes_commitment`, `should_escalate`, `uses_only_permitted_information`, `language`); `None` for owner-dictated text. They are stored in `actions.draft_flags`, never in `policy_decision` (Tx A overwrites that).
- **One expiry rule** (decisions R7, amended by owner decision 2026-10-30, P2-O20): `expires_at = now + max_age` is set **once, at proposal**, for every proposable (owner-approved) action — our window estimate never shortens or expires it; a new version never extends it. Only an autonomous action (`lifecycle.window_bounds(origin)`) is also bounded by `closes_at(anchor) − SAFETY_MARGIN` (`apply_new_version` shortens it) and gets `window_closed` from `expire_due`/`approve` when its window is closed now; every other expiry is `max_age`. Telegram's refusal of an owner-approved send (`PEER_ID_INVALID`) is S04.4's `expired`/`window_closed`.
- `_supersede_live` moves at most one row (the partial unique index guarantees it) and clears its token; the old card is refreshed by S04.3's sync. The transition writes `action_superseded` (reason `superseded`; details add `superseded_by`).
- Audit rows come only from the transitions (§3.6, decisions R15): the insert writes none; `proposed → awaiting_approval` writes `action_proposed`, `proposed → blocked` writes `action_blocked` (details add the failed rule names). Content-free.
- **Blocked proposals do not supersede** a live sendable card: a draft that cannot be sent must not destroy one that can. The card for a blocked proposal still shows the text as copy-ready (S04.3).
- `ProposalRefused` is a domain error; tools report it as a factual error ("not available"), never as success.
- Never sends a card, never defers a job: callers do (`ApprovalCardPresenter.present_after_commit`, S04.2/S04.3).

### 3.6 Single-action transitions (`actions/lifecycle.py`)

All go through one primitive (F0-interfaces §2):
```python
async def transition(session, *, account_id: int, action_id: int, from_state: ActionState,
                     to_state: ActionState, reason: StateReason | None, now: datetime,
                     expected_version: int | None = None, token: str | None = None,
                     values: Mapping[str, Any] = {}) -> bool
```
— asserts `(from_state, to_state) in TRANSITIONS` (F0; it includes `executing → expired` and `proposed → cancelled`, decisions R4); one `UPDATE … WHERE id = :id AND account_id = :a AND state = :from [AND version = :v] [AND approval_token = :t] RETURNING id`; sets `updated_at`, `state_reason`; clears `approval_token` whenever the new state is not `awaiting_approval`; writes one audit row with `details = {"from", "to", "version", "reason"}` (plus `attempt_id` when `values` carries one — the claim and send outcomes); returns whether it applied.

**Audit event per transition** (F0-interfaces §11, decisions R15), chosen inside `transition` from the pair and reason — callers never pick event names:

| Transition | Event |
|---|---|
| `proposed → awaiting_approval` | `action_proposed` |
| `revising → awaiting_approval` with a new version (`apply_new_version`) | `action_edited` |
| `revising → awaiting_approval`, same version (`cancel_edit`, `revision_failed`) | `action_revision_cancelled` |
| `→ revising` | `action_revision_requested` |
| `awaiting_approval → approved` | `action_approved` |
| `executing → approved` (429) | `action_rate_limited` |
| `→ rejected` | `action_rejected` |
| `→ blocked` | `action_blocked` |
| `→ outdated` | `action_superseded` when the reason is `superseded`, else `action_outdated` |
| `→ expired` | `action_expired` |
| `→ cancelled` | `action_cancelled` |
| `approved → executing` | `action_claimed` (details add `attempt_id`) |
| `→ succeeded` / `→ failed` / `→ delivery_uncertain` | `action_succeeded` / `action_failed` / `action_delivery_uncertain` (details add `attempt_id`); from `delivery_uncertain` (a late result) `action_late_result` |

Then:

| Function | Transition | Used by | Notes |
|---|---|---|---|
| `approve(session, *, account_id, token, now) -> ApproveResult` | `awaiting_approval → approved` | S04.3 | Matches by token (bound to the version, since tokens rotate per version) and `expires_at > now`; sets `decided_at`, `approved_text_hash = sha256(text)`; result `APPROVED(action_id, version)` / `EXPIRED` (it then applies `→ expired` with `window_closed` or `max_age`, whichever holds) / `NOT_ACTIVE` (unknown, foreign, used, revising). The caller defers `actions.execute` in the same transaction |
| `reject(...)` | `awaiting_approval → rejected` | S04.3 | `owner_rejected`; `decided_at` |
| `start_edit(...) -> int` | `awaiting_approval → revising` | S04.3 | Returns the version being edited; token voided (Approve while revising answers "no longer active") |
| `set_revision_turn(session, *, account_id, action_id, expected_version, turn_id: int \| None) -> bool` | none (stays `revising`) | S04.3 | Records (or, with `None`, clears — after a `TOO_LONG`/`EMPTY` revision) the owner's revision message in `actions.revision_turn_id` (decisions R8) — `WHERE state = 'revising' AND version = :v`; no audit row (the `→ revising` row exists) |
| `cancel_edit(...) -> str` | `revising → awaiting_approval` | S04.3 | Same version, **new** token; clears `revision_turn_id` |
| `apply_new_version(..., expected_version, text, draft_run_id, draft_flags, shown_through_message_id, base_message_id) -> NewVersion` | `revising → awaiting_approval` | S04.3 | `version + 1`, new token, new text, new `draft_flags`; clears `revision_turn_id`; `WHERE state = 'revising' AND version = :expected`; `expires_at` never extended, only shortened if the window now closes earlier (the one expiry rule, decisions R7); a too-long or empty text returns `TOO_LONG`/`EMPTY` and leaves the row `revising` (S04.3 tells the owner); a stale version returns `STALE` and writes nothing |
| `revision_failed(...)` | `revising → awaiting_approval` | S04.3 | Same version and text, new token, clears `revision_turn_id`, when a revision run fails |
| `expire_due(session, *, now) -> list[int]` | `awaiting_approval`/`revising`/`approved → expired` | S04.3 job | Reason `window_closed` if an autonomous action's window is closed now, else `max_age` (owner decision 2026-10-30, P2-O20); never touches `executing` |

The executor's claim and outcome transitions (`approved → executing`, `executing → …`) are S04.4's, built on `transition`.
