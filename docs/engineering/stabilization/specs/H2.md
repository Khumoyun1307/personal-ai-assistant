| Item | Specification |
|---|---|
| Goal | Route next owner answer and explicit Telegram reply to the correct durable task/card. |
| Contracts | [C1](../contracts/C1-request-state.md), [C3](../contracts/C3-receipts-and-card-facts.md) presentation map, C4 mixed-text handling, C5 selection. |
| Dependencies / lane | H1; ingress/context/runtime first, before H12; registry after Q1/Q3. H3 prepares separately but shared context/registry edits sequential. |
| Files | `telegram/control/{inbox_handlers,handlers,dispatcher,approvals}.py`; `accounts/models.py`, request service; `agent/{context,runtime,persistence}.py`, registry seams; migration for reply metadata. |

| Acceptance ID | Exact criterion |
|---|---|
| H2-1 | `IncomingMessage` and persisted ControlTurn retain reply_to control message ID; resolve within account/control namespace via current pointer or successful presentation mapping. No text/name copied into metadata. |
| H2-2 | Precedence: explicit reply artifact → active pending clarification → focused request → standalone bare-phrase search. “Kamola Ziyo”, “20”, “shorter” fill relevant slots instead of unconditional search. |
| H2-3 | Two cards in different conversations: direct reply to k edits k/presented version, n untouched. Stale/unavailable/foreign target never silently falls back to newest card. |
| H2-4 | Topic switch suspends/cancels old focus as C1; old body never transferred to new recipient. Explicit return resumes retained request; expired/missing source reports unavailable. |
| H2-5 | Forwarded text never treated as owner pending answer; separate own-text instruction beside quote preserved for H12, quote remains untrusted. Existing command/kill-switch handling wins. |
| H2-6 | Restart with question row missing can recreate question from request facts without synthesizing task text; stale question/card does not hijack unrelated owner input. Source request and action version unchanged by mere recipient clarification. |
