## H4 schema and routing inputs for the prompt steward (2026-11-10)

The implemented strict schemas live in `agent/tools/owner_composition.py`:
`ProposeOwnerMessageArgs` and `ReviseOwnerDraftArgs` match C2's flat field sets.
With `tool.propose_owner_message` on, `for_run` omits `propose_reply` and substitutes
the flat `revise_draft` definition. Both still require managed consent; without
it they are content-free blocked stubs. Keep the flag off until the H10 checker,
its atomic version binding and execution hooks exist. H4 wires a typed optional
checker through bootstrap/runtime/ToolServices; absence never passes.

- Compose/reply: write the complete body in the main conversation; use exact C1
  owner instructions and C8 effective preferences, preserve their provenance,
  and treat contact/quoted/derived text as untrusted. Do not delegate writing.
- Literal dictation: call `propose_message` with retained C1 source IDs; do not
  supply or reconstruct text. Advice and list editing need no message action.
- A standalone task without substance returns `proposal_status=needs_input`,
  reason `content`; ask what to write. Invalid sources/arguments have no artifact
  and no effect; never infer one from a different live card.
- Reply requires the request's explicitly selected retained target and a read
  fence, without a separate composition brief. `new_message` has
  answered_message_id=null. No newest-target fallback.
- Read the actual draft before claiming its contents or composing a revision.
  Supply the full rewrite and expected_version, or exact source IDs for a literal
  append/replacement. A generated rewrite stays assistant-written. C1-ready
  revisions with literal change sources need no separate composition brief.
- The fence ID is application-issued and run/request-bound. Never invent one.
  H10 may validate a source-only snapshot for literal edits with a null ID.
- Wire `status` retains the compatibility vocabulary; `proposal_status` carries
  C2 detail. `action=null` means no artifact. `requested_change_applied=false`
  means this call applied nothing, including reuse/conflict. Exact retries return
  the original effect version plus fresh current action facts.
- Stored/queued is not presented; presented is not sent. A current token tap,
  policy re-check and committed claim are still necessary. Warn without inventing
  a new dead-end approval state (D-S17). Never regenerate through a legacy writer
  after errors or conflicts. Use explicit current-version revision instead.

No used prompt bytes or registry activation change in H4. J28/I02/J04/J05 remain
dependent on H6/H10 runtime integration; do not remove their strict xfails merely
because the tool schema exists. The full repaired journey/retrieval paid gates
must run with separately authorized cost before enabling the flag.
