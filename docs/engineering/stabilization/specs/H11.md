Review fixes (2026-11-12; unverified): intent-changing card presses and legacy
`revise_draft` now take conversation UPDATE before requests/actions, avoiding
concurrent SHARE-to-UPDATE upgrades. PostgreSQL regressions sequence card
Reject/Edit against chat revision in both winning orders, without timing sleeps.
Card-backed intent changes preserve the pending flag for contact messages newer
than the affected card's coverage; Cancel edit regressions cover a recoverable
newer burst and consumption of the old burst, and a real-ingestion Reject
regression permits a fresh Assist draft for the newer message. Source-change regressions retain
Assist-path arrival/edit/deletion warnings and owner-requested manual takeover.
The Cancel edit regression seeds the persisted contact arrival/flag while the
card remains revising: the existing ingestion warning transition separately
moves revising cards to OUTDATED and can make that cancellation stale.

CI repair (2026-11-17): Assist no longer yields to an approved/executing send;
only a live explicit or warning card blocks it, so a newer contact burst still
gets a card (H11-4) while approved work stays under the claim protocol (H11-6).
Revision 0025 deletes an account's owner requests in a `BEFORE DELETE` trigger
on `accounts`, so a request-linked action (now also set by `propose_message`)
no longer aborts the physical account cascade. The state-machine regression
tolerates only H11's specified background refusals (`takeover`,
`owner_intent_superseded`) for proactive proposals. Relevant suites pass in the
worktree container; the full suite runs in CI; H8 merge validation and manual
Telegram checks remain pending.
