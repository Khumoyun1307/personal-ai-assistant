## 3. Content

### 3.1 Rules for every scenario in this package

1. **File header.** `pytestmark = pytest.mark.integration`; one fixture per test; the rest through `steps.py`.
2. **Environment.** `m07_env` calls F0-E's `p3_environment(migrated_url, flags=..., settings=...)`; if the driver has no `settings` keyword at CP1 (contract gap; QA-X §2.2 adds it), the fixture sets the values with `monkeypatch.setenv` (for example `EXPORT_MAX_PART_MB=1`) before entering the environment. The account timezone is set through the owner's preferences (the `M05Scenario.preferences(timezone=…)` path). The clock starts at the driver's `NOW`, Sunday 2026-10-18 12:00 UTC (17:00 in `Asia/Tashkent`, the default timezone below; 14:00 in `Europe/Berlin`).
3. **Marker.** A scenario that cannot pass on the CP1 base is `@pytest.mark.xfail(strict=True, reason="awaiting <ID>")`, with `<ID>` the "Turns green" unit below: the unit planned to merge last among the scenario's needs (README §3 schedule; ties go to the unit whose behaviour the scenario proves). `<ID>` is always a unit id from the README §3 index. A scenario green on its base is unmarked; if one that should be green on the base fails, the defect belongs to the F0 unit that owns the behaviour: QE1 files it on that unit's issue with the scenario as evidence and marks the scenario `awaiting <that unit>` until the fix PR (QA-X §3.1 rule 3). Parametrised cases that turn green at different merges carry their own `pytest.param(..., marks=...)`.
4. **A skeleton is a complete test.** The D+1.5 PR holds every scenario with its full body (a body-less strict-xfail test would XPASS).
5. **Positive control.** Every scenario that asserts an absence also asserts a positive outcome in the same test, so it cannot pass vacuously before the feature exists (the P2 #109 lesson): for example "no missed reminder" is asserted together with "one `follow_up_met` delivered".
6. **Imports.** Module level only for names present at CP1 (`assistant.core.{flags,jobs}`, `assistant.inbox.notification_types`, `assistant.memory.models` constants, ORM models, `tests.integration.{business_env,agent_env,p2_factories,p3_factories}`, `tests.scenarios.{p3_drive,p2_drive}`, `tests.log_hygiene`). Never import a module a later unit creates at module level.
7. **Seeds** only for state the scenario does not test, with the comment "seeded: not under test"; the behaviour under test goes through its real entry point (ingestion, tool + card, callback, command, `system.reconcile_schedules` + `automation.fire`, jobs).
8. **Determinism and data.** `FakeClock` only; no sleeps; synthetic English text (≥ 6 words); canaries `CANARY-SYNTH-P3-<n>`; documents are synthetic Telegram payloads (`business_message(extra={"document": {"file_id": "synthetic-file-<n>", "file_unique_id": "synthetic-u<n>", "file_name": "synthetic.pdf", "mime_type": "application/pdf", "file_size": 1024}}, message_text=None)`). Assertions read ids, states, reasons, codes, counts, notification rows and audit `details`; text only where the text is the subject (exact local time in an echo, "late", "Snoozed", "sent" never used early).
9. **Markers come off on the feature unit's branch (R47).** A feature PR never edits `tests/scenarios/m07/`. When a scenario marked `awaiting <ID>` starts to pass on that unit's branch, CI turns red (strict XPASS); the unit's author tells QE1 on the unit's issue and QE1 pushes one commit to the unit's branch that removes exactly the markers of the scenarios that pass (P3-interfaces §15.1). Whichever of this PR and a unit PR is ready first merges; a unit already merged when this PR is rebased has its markers dropped by QE1 in this PR (P2-T48). Nobody else edits a scenario; never delete or weaken one.
10. **Expected-failure classification** in the PR description: each scenario run unmarked on the base, its first failure point recorded; a failure caused by the scenario itself is fixed, never marked.
11. **Tool arguments.** `owner_tool` passes every field of the tool's strict args model; the schemas have no defaults, so an omitted nullable field is a validation error. The M07 models: `create_reminder(text, at, recurrence, conversation_id, contact_id)`; `update_task(task_id, op, snooze_until)` with `op` in `complete`, `snooze`, `cancel`, `reopen`; `create_follow_up(conversation_id, task_id, expected, description, deadline, draft_nudge)`; `create_automation(kind, scope, period, at, recurrence, expires_at)`; `update_automation(automation_id, op, at, recurrence, scope, period, text)` with `op` in `pause`, `resume`, `reschedule`, `edit`; `delete_automation(automation_id)`; `list_tasks(status, kind, include_snoozed, conversation_id, contact_id, limit)`; `list_automations(kind, include_ended, limit)`. A `recurrence` object always carries `frequency`, `time`, `weekdays`, `interval_days`, `starts_on`.

### 3.2 Helpers (`steps.py`)

| Name | What it does |
|---|---|
| `owner_tool(s, tool, *, forwarded=False, **args)` | Owner run with one scripted tool call and a closing text (the `M05Scenario.owner` pattern); returns the tool result dicts |
| `confirm(s)`, `cancel(s)` | Press Confirm / Cancel on the live `tool_confirm` card; drain `agent.apply_confirmation` |
| `press(s, kind, op)` | Press `op` on the live card of `kind` (`business_env.press`) |
| `fire_due(s)` | Run the periodic `system.reconcile_schedules`, then drain `automation.fire` |
| `drain(s, task)` | `s.require(task)` (xfails when unregistered), then `p2_drive.run_queued` |
| `deliver_alerts(s)` | Drain `notify.deliver` |
| `advance_to(s, utc)` | Set the clock forward to an instant (never backwards) |
| `contact_says(s, number, text, *, chat=None, date=None)`, `contact_document(s, number, *, chat=None, date=None)`, `owner_manual(s, number, text, *, chat=None)` | Real ingestion of a contact message, a contact document or an owner-authored business message |
| `triage_commitment(s, message_id, *, text, due)` | Queue a triage result with one contact commitment (`{"by": "contact", "text": …, "due": …, "source_message_id": …, "existing_task_id": None}`, the M05 shape) and drain `inbox.triage`; returns the task id |
| `follow_up(s, *, chat, task_id, kinds=("document",), deadline, draft_nudge=True, description="Synthetic: the signed documents")` | `owner_tool("create_follow_up", conversation_id=…, task_id=…, expected={"kind": "media_received", "terms": [], "media_kinds": list(kinds)}, description=…, deadline=…, draft_nudge=…)` then `confirm`; returns the automation id |
| `reminder(s, *, text, at=None, recurrence=None, conversation_id=None, contact_id=None)` | `owner_tool("create_reminder", …)`; confirms when a card is shown; returns the tool result |
| `nudge_draft(**changes)` | A `DraftResult` dict (`draft_reply.v1` shape, the `p2_drive.draft_result` keys) with `text="Synthetic gentle reminder about the documents."` |
| `candidates(*items)` | A `MemoryCandidates` dict: `{"language": "en", "candidates": [...]}`; each item `{"scope", "kind", "category", "text", "source_message_ids"}` |
| `revoke(s)` | `s.revoke()` of `ai_managed` only (the driver's `/privacy` managed choice; the owner keeps `ai_control`). If the driver helper revokes both consents, QE1 asks SQ for the narrower helper (QA-X §2.2) |
| `contact_deletes(s, number, message_id)`, `contact_edits(s, number, message_id, text)` | Real ingestion of a `deleted_business_messages` and an `edited_business_message` update for a stored contact message (K9) |
| `notifications(s, kind)`, `tasks(s)`, `automations(s)`, `occurrences(s, automation_id)`, `audits(s, event)`, `memory_items(s)` | Account-scoped reads |
| `business_sends(s)`, `control_texts(s, start=0)`, `documents(s)` | Fake transport recordings (documents: the GW-DOC sender fake's `documents` list; bytes through the driver's recorder, QA-X §2.2) |

In the tables, "run `system.…`" means `s.run_periodic(...)` and "drain `<task>`" means `drain(s, task)`. **Scripted model outputs** (triage results, `MemoryCandidates`, nudge and summary drafts) are queued immediately before the job that consumes them, and the helper asserts afterwards that `FakeLLM.parsed` is empty, so a job that did not run fails loudly instead of handing its output to the next model call. A step that must not reach the model gets no scripted output.
