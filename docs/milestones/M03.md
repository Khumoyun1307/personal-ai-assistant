| D44 | **Normaliser v2 = ASCII canonical form** (owner, 2026-10-22; D41 in M02.md): NFKC + casefold; every apostrophe-like character (ʻ ʼ ‘ ’ ' \` ´ ʹ ʽ ′) folded, then dropped; oʻ/o'/ö/ō/ŏ/ó → o; gʻ/ğ/ǵ → g; ş → sh, ç → ch, ñ → ng; Cyrillic → Latin with the Uzbek table (ў→o, ғ→g, қ→q, ҳ→h, х→x, ш→sh, ч→ch, ё→yo, ю→yu, я→ya, ц→ts, е→ye word-initially or after a vowel/ъ/ь else e, ъ/ь dropped) plus the Russian letters (щ→shch, ы→i, э→e, й→y); whitespace collapsed. `NORMALIZER_VERSION = 2`; `reindex-search` re-keys all retained rows and records the global `system_state.normalizer_version`. The spike prototype (`spikes/search/normalize_proto.py`) was ported, never imported. | People type Uzbek without the new alphabet or apostrophes; one key for 1995 Latin, new Latin, apostrophe-less Latin and Cyrillic. | D53 | **Forwarded or quoted text from a managed chat is managed content** (review item O): the control inbox collects the origin (forward sender/chat, legacy `forward_*`, `external_reply` origin and chat, a forwarded message replied to); when it matches one of the account's contacts or conversations — or a hidden sender's name equals a contact's — the turn is stored `contains_managed`. | D55 | **Held-call hardening** (review items A, B, C, F, H): success is reported only for status `ok`; a handler exception ends `failed` with an "it may not have been applied" notice; a card shows the arguments in full (bidi and invisible characters made visible) or the call is refused; a repeated call reports the row's real state; the same pending change from a retried turn reuses its card; an ambiguous card send expires the card; `confirmed` rows whose job is lost are re-deferred by `system.reconcile_pending` and failed by the retention sweep after 24 h; the worker cannot be built without an applier. | Invariants 3b and 11. |
| D56 | **Taint decays** (lead decision on review round 2; **confirmed by the owner on 2026-10-23 by merging PR #10**): (a) every reply written by a tainted run (own or inherited taint) is shown to later runs wrapped as untrusted (`control_turns.from_tainted_run`, revision 0009); (b) only a reply whose run was tainted by its OWN inputs — the current turn's forwarded/quoted/managed text, or an untrusted tool result in that run — taints later runs (`third_party`); inherited-only taint does not propagate, and a reply's managed content read from history no longer counts either. | D55's "reply carries the taint" made taint permanent: every later configure call needed a card. | D60 | **Summary refresh cadence (S03.2):** a chat's rolling summary is refreshed once it has been quiet for 30 minutes (`SUMMARY_REFRESH_DEBOUNCE_MINUTES`), or at the latest 6 hours after its first unsummarized message (`SUMMARY_REFRESH_MAX_WAIT_HOURS`) — a trailing debounce: the job re-defers itself while messages keep coming. One incremental call per refresh (≤ 200 new messages per call, ≤ 5 calls). The reconciler re-creates a lost job one debounce out, so a chat whose refresh keeps failing is retried at most about twice an hour. **Pending owner confirmation.** | Summaries are long-term memory and get_conversation context, not alerts: freshness of minutes is not needed, and a quiet period groups a burst into one paid call. The catch-up does not depend on this cadence (it summarizes its period on demand). |
| D61 | **Background refresh is behind a release flag** `summary.refresh` (FEATURE_FLAGS), **default off**, like every tool. While off, content is still flagged (`pending_ai_since`), no job is queued, and the read tools summarize on demand. **Pending owner confirmation.** | It spends model budget without an owner request; the owner turns it on when ready (it is also what the S03.3 retention rollup will rely on). |
| D62 | **"Needs reply" check (attention list v1)** = the rolling summary's `needs_reply` and reason — no separate call type. When the attention list is asked, up to 8 chats whose summary is stale are refreshed inline with **one summary call each, never chained** (the same incremental call the background job would make, moved earlier); a chat with more unseen messages than one call reads (200), or whose refresh fails, shows `not_checked`, as do stale chats beyond the 8. Cost per ask: at most 8 summary calls, plus at most one retry of a truncated output each, plus — only when a chat changed during its call (owner addition to D63/D66) — one immediate repeat of that chat's call (itself with at most one truncation retry): 32 in the theoretical worst case, 8 normally, only for stale chats (review item 5). **Pending owner confirmation.** | No extra prompt or route to evaluate before S03.4; the verdict comes from the same summary the owner sees, and its cost is bounded. Triage (M05) upgrades it. |
| D63 | **A deleted message invalidates the summaries that covered it:** its chat's period caches are deleted, and the rolling summary if it covered the message; the rolling summary is rebuilt from the retained messages, and content that had already expired is recorded in `summary_gap_before` (answers then say earlier messages expired without a summary). **Owner addition (2026-10-25), also for D66:** when a summary is discarded because the chat changed during the model call (a deletion or edit), a background refresh says nothing and rebuilds at the next refresh (the flag stays set); an owner-requested path (`summarize_period`, the attention list's inline check) retries that chat once at once with the fresh messages, and if the retry is discarded too, returns the chat as NOT summarized (`changed_during_summary`) — never as an empty or complete summary (invariant 11) — with a notice written by our code ("…changed while it was being summarized (a message was deleted or edited), so it was left out. The cost is losing summarized context of expired messages in that chat. |
| D64 | **Catch-up = map per chat, deterministic combine:** one period summary per active chat (≤ 15 chats per catch-up, the newest ≤ 300 messages each, 4 calls in flight), cached as `kind = period` while the range's messages are unchanged (30-day retention); the combination (grouping needs-attention → commitments → other, the list of chats not summarized, coverage caveats) is done in code, and the owner model writes the reply. Caveats are the application's own English sentences; the prompt requires every one to be relayed. **Pending owner confirmation.** | One call per active chat keeps isolation (invariant 4) and cost linear; deterministic caveats cannot be dropped by a model before they reach the owner-facing model. The S03.4 evaluation measures whether the final replies keep them. |
| D66 | **An edit of a covered message is treated like a deletion (D63)** (review item 2, coordinator decision 2026-10-25): an edit that changes a message's content drops the chat's period caches and, if the rolling summary covered the message, the rolling summary too; it is rebuilt from the retained messages (with the new text). | D67 | **`remember` stores the owner's words, not a paraphrase:** the model drops only the "remember that" framing and adds nothing (prompt rule, `owner_request.v4`); code trims and stores the text as given (1–400 characters, the confirmation card must show it whole). | D70 | **Memory from other people's text** (revised 2026-10-26 by the safety review; the first version — such items preloaded wrapped and never tainting — contradicted invariants 3b and 9 and is withdrawn). Restating it cannot launder it (the restating run's context carries the tainted reply). The owner's own items (from untainted runs) are preloaded verbatim (≤ 30, newest first) as an input item with provenance; notes about contacts come only through `list_memories`. **Pending owner confirmation of the trade-off:** a run that read such an item needs a card for any later change in that run, and a note saved within 20 turns of a tainted reply is itself treated as from other people's text. | Invariant 3b: other people's text must not reach a run without tainting it, and nothing derived from it may pass as the owner's words. | D85 | **Retention edges** (S03.5 safety review 7; general review 11, 12): a stored value that is set but invalid reads as the class's **shortest** period (fail safe), unset as the default (narrows D80). | E-b | **Open-loop recall** is over open questions plus open commitments (README).
