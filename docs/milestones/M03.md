## Decisions

Decisions recorded while building M03. Owner decisions carry their date; the
agent's own choices that the owner has not yet confirmed are marked
**pending owner confirmation**.

| # | Decision | Why |
|---|---|---|
| D44 | **Normaliser v2 = ASCII canonical form** (owner, 2026-10-22; D41 in M02.md): NFKC + casefold; every apostrophe-like character (ʻ ʼ ‘ ’ ' \` ´ ʹ ʽ ′) folded, then dropped; oʻ/o'/ö/ō/ŏ/ó → o; gʻ/ğ/ǵ → g; ş → sh, ç → ch, ñ → ng; Cyrillic → Latin with the Uzbek table (ў→o, ғ→g, қ→q, ҳ→h, х→x, ш→sh, ч→ch, ё→yo, ю→yu, я→ya, ц→ts, е→ye word-initially or after a vowel/ъ/ь else e, ъ/ь dropped) plus the Russian letters (щ→shch, ы→i, э→e, й→y); whitespace collapsed. `NORMALIZER_VERSION = 2`; `reindex-search` re-keys all retained rows and records the global `system_state.normalizer_version`. The spike prototype (`spikes/search/normalize_proto.py`) was ported, never imported. | People type Uzbek without the new alphabet or apostrophes; one key for 1995 Latin, new Latin, apostrophe-less Latin and Cyrillic. ARCHITECTURE §11.2. |
| D45 | **Taint** (owner clarification 2026-10-22; D42 in M02.md): the agent reads and works with everything; a run is tainted when its context includes third-party text — the current owner message with forwarded/quoted text, included history turns carrying such text or managed content, or tool results with contact-authored text. In a tainted run only model-initiated `configure`/`control` calls (other than `pause_autonomy`, `end_delegation`, cancel) become a one-tap confirmation card; reads are never blocked; the owner's direct commands and buttons need no card. `resume_autonomy` never runs from a model call. | Invariant 3b without blocking the agent's real work. ARCHITECTURE §7.1. |
| D46 | **Quoted text is stored** as `control_turns.quoted_text` (a new content column: registered in `privacy/content_columns.py`, ARCHITECTURE §10.1/§10.4, the deletion cascade and the retention sweep); forwarded text is the message text itself; `control_turns.third_party` marks either. | The agent must understand what the owner quoted; the column is covered like every other content column. |
| D47 | **Read tools** `search_messages`, `resolve_contact`, `get_conversation`, `list_conversations`: class `read`, run types {`owner_request`}, `min_tier = CONTROL_ONLY` (stored history stays readable while the connection is disabled), `returns_managed = True` (omitted without `ai_managed`), release flags `tool.<name>` default off. | ARCHITECTURE §8.2, §14.3; AGENTS §8. |
| D48 | **Per-route model configuration** `LLM_ROUTE_<RUN_TYPE>_MODEL` (default `LLM_DEFAULT_MODEL`). The processor of a route is derived from its model id in one table (`core/model_routes.py`: `gpt-*` OpenAI, `claude-*` Anthropic, `gemini-*` Google); the consent wrapper refuses an unknown model, a model of a processor the adapter does not serve, and a processor the consent does not name. | ARCHITECTURE §7.4; needed for the "route configured to a processor not named in the consent raises" test. Deriving the processor from the model keeps it to one setting per route, not two that could disagree. |
| D49 | **A forwarded control-chat message is never a command**, stop word or pending-input answer: it goes to the agent as a tainted turn. **Pending owner confirmation.** | Its text is someone else's; running a forwarded `/privacy revoke` would let a third party's text act as the owner (invariant 3b). The owner can still type the command. |
| D50 | **What counts as quoted third-party text:** a `quote` from another chat (`external_reply`) or from a forwarded message the owner replies to; an `external_reply` without a quote does **not** taint, because `ExternalReplyInfo` carries no text we store; a quote inside a forward belongs to the forward. **Pending owner confirmation.** | D45 taints on third-party text *in the context*; text we never store cannot be in it. Avoids wrapping the owner's own words as untrusted. |
| D51 | **`tool_confirmations.status` has two more values than planned** — `applied` and `failed` besides pending/confirmed/rejected/expired. | "Confirm applies once" needs a durable claim: the job moves `confirmed → applied` with a conditional UPDATE before running the handler (at most once, like every card), and a handler error ends as `failed`, never as done (invariant 11). |
| D53 | **Forwarded or quoted text from a managed chat is managed content** (review item O): the control inbox collects the origin (forward sender/chat, legacy `forward_*`, `external_reply` origin and chat, a forwarded message replied to); when it matches one of the account's contacts or conversations — or a hidden sender's name equals a contact's — the turn is stored `contains_managed`. Without `ai_managed` the model gets a "withheld" note instead of the text; managed-data deletion clears it. An unknown origin is not managed (nothing stored to match). **Pending owner confirmation.** | AGENTS §6 invariant 9: control turns that quote managed content need `ai_managed`. |
| D54 | **Query-side spelling alternatives** (review item K): each query term also matches zh↔j, kh↔x, x↔h, y↔i, k↔q, u↔o and initial e↔ye (one rule at a time, ≤ 24 alternatives per term). The stored key is unchanged, so write and query stay symmetric. | Russian typed in Latin (zhdu, ego, vy, khorosho) and Uzbek on a Russian keyboard (куп, raxmat) missed short words that trigrams cannot rescue. More recall, some extra noise; the S03.4 retrieval eval will tune it. |
| D55 | **Held-call hardening** (review items A, B, C, F, H): success is reported only for status `ok`; a handler exception ends `failed` with an "it may not have been applied" notice; a card shows the arguments in full (bidi and invisible characters made visible) or the call is refused; a repeated call reports the row's real state; the same pending change from a retried turn reuses its card; an ambiguous card send expires the card; `confirmed` rows whose job is lost are re-deferred by `system.reconcile_pending` and failed by the retention sweep after 24 h; the worker cannot be built without an applier. | Invariants 3b and 11. |
| D56 | **Taint decays** (lead decision on review round 2, **pending owner confirmation**): (a) every reply written by a tainted run (own or inherited taint) is shown to later runs wrapped as untrusted (`control_turns.from_tainted_run`, revision 0009); (b) only a reply whose run was tainted by its OWN inputs — the current turn's forwarded/quoted/managed text, or an untrusted tool result in that run — taints later runs (`third_party`); inherited-only taint does not propagate, and a reply's managed content read from history no longer counts either. | D55's "reply carries the taint" made taint permanent: every later configure call needed a card. With (b) the taint ends once its source leaves the 20-turn window; (a) keeps the model from treating a restated injection as the owner's words. |
| D52 | **Tool argument constraints are validated in Pydantic validators, not as JSON-schema keywords**; dates are `YYYY-MM-DD` strings in the owner's timezone (inclusive), not `format: date`. | OpenAI strict mode's support for `format`/length keywords was not verified against the official docs in this slice (no live call was allowed); plain strict schemas are known to work (S01.4). A unit test keeps those keywords out of every tool schema. |

  D52): `search_messages`, `resolve_contact`, `get_conversation`,

### Delivered

- **Runner** (`python -m evals verify|run|compare`, `evals/cli.py`,
  `runner.py`, `report.py`): refuses unless the datasets match the frozen
  manifest; runs a target; writes `docs/evals/<date>-<set>-<model>.md` and a
  `.json` beside it; `compare` tabulates quality and cost per 100 items per run.
- **Target interface** (`evals/targets.py`): `EvalTarget` (name, dataset, route,
  `uses_model`, `plan`, `run`), `MetricResult` with a pre-screen and a gate
  measure, and a marked **placeholder** `SummaryTarget` (exit code 3) for after
  S03.2.
- **Retrieval target, wired** (`evals/retrieval.py`, `corpus.py`): the real
  `memory.retrieval.search_messages` over the E1 corpus in a **throwaway
  migrated database** (`assistant_eval_<random>`, created and dropped by the
  run; `EVAL_DATABASE_URL`, default `TEST_DATABASE_URL`, never `DATABASE_URL`),
  loaded as the product stores messages (current text, tombstones for deletions,
  never `original_text`/`purged_text`). Modes: `deterministic` (no model) and
  `variants` (model-written query variants through the `LLMClient` port, then a
  final answer checked mechanically).

  (`evals/review.py`). **What a model may see** (`evals/render.py`): messages and

### Decisions (agent's choices, all **pending owner confirmation**)

| # | Decision | Why |
|---|---|---|
| E-a | **Gate versus pre-screen.** Every metric is recorded over all items (pre-screen) and over owner-confirmed items (gate). With no confirmed items, a run that stopped early, a pending judge flag or an unresolved open loop, the gate reads `NOT EVALUABLE`, never a pass. The owner's decisions live in a JSON ledger (`evals/reviews/<dataset>.json`, `--reviews`): confirmed conversation/query ids, verdicts on judge flags, covered/missed on open loops. | §10.1: gate results count only owner-confirmed items; the LLM judge only pre-screens. The datasets are frozen, so review state cannot live in them. |
| E-b | **Open-loop recall** is over open questions plus open commitments (README). An item counts as surfaced only if *every* `values` string occurs in the summary (compared in the product's ASCII form, so script, apostrophes and punctuation do not matter). **42 of the 103 open loops in E1 v1 have no `values`**, so string matching cannot decide them: the judge pre-screens them, the gate needs the owner's verdict, and without it they leave the gate open. | Conservative and honest: a looser rule would let a paraphrase-blind check pass items it cannot see. The owner may prefer adding `values` in v1.1 to ruling on 42 items. |
| E-c | **Fabrication** is an LLM-judge pre-screen only: the judge sees the chat, the `must_not_state` traps and the summary and flags statements. Every flag starts pending; only owner-confirmed flags count against the zero threshold; a conversation the judge could not screen leaves the gate open. | Fabrication cannot be decided by string matching in the owner's language; §10.1. The judge receives labels (traps); the summariser never does. |
| E-d | **Caveats are structured output** of the summary target (gap ids named, a pre-connection flag), not parsed from prose. Presence is per conversation with expected caveats (100 %); a caveat for a gap that lost nothing (delayed-only), an unknown gap, or a pre-connection note without a coverage start is *spurious* (threshold 0). | The S03.2 renderer knows deterministically which gaps it reported; README says a delayed gap must not be reported as possibly missing. The spurious-caveat threshold is stricter than the plan's text. |
| E-e | **Owner-facing language/script** is a deterministic heuristic: at least 80 % of the letters in the owner's script, and the language (Uzbek/Russian/English) detected from a small list of function words with at least two hits and a clear winner; doubt fails. | "Correct 100 %" needs a mechanical check; it can be too strict (never too lenient). To be calibrated on real S03.2 outputs. |
| E-f | **Variants mode** uses an eval-side prompt (`evals/prompts/retrieval_variants.v1.md`) that mirrors `owner_request.v2.md` rule 5; the owner's own query is always searched with at most five variants (six in all, the service limit), top 5 results. It measures the model's variant writing plus the service, **not** the full agent loop (no tool-call format, no agent run). | An end-to-end agent run needs a control chat, consent and jobs; this is the offline, cheap version. If it clears the threshold, an agent-level spot check on the dev bot is the owner's call. |
| E-g | **"Correct final answer with reference"** is mechanical: `found`, every reference valid (a real result, contact, day in Asia/Tashkent, a quote that is verbatim in the message), at least one reference to a target message, and every `answer_values` string in the answer or quotes. A translated or reformatted value fails. The reference is read from structured fields, not free text. | No judge decides the 80 % gate. Strict on purpose; the production agent answers in free text, so this measures capability, not format. |
| E-h | A failed model call (provider error, refusal, truncation) is a **miss** and listed; a query with no hits skips the answer call and counts as wrong; queries run at a fixed instant (last message + 1 day) so the recency bonus is reproducible. | Conservative; reproducible baselines. |
| E-i | **Cost guard**: worst case = input at 2 characters per token plus the full `max_output_tokens` per call; a run over the cap does not start; each call is refused when spent + its worst case would pass the cap; a call that fails with invalid output is billed at its worst case; a model with no price is refused (`--price` supplies one). The cap (default USD 1) is per run: the USD 1 *total* is tracked through the reports, not enforced across runs. | The cap must hold even when reasoning tokens make usage unpredictable. A cross-run ledger would be infrastructure for later. |
| E-j | Evaluation runs send **synthetic data only**, so their client stack has the budget wrapper but not the consent wrapper (no account, no consent row); in-memory metering, no `llm_calls` row. Requests are still labelled with honest provenance. | §14.3 guards owner data. Recorded so a reviewer does not read the missing wrapper as an omission. |
