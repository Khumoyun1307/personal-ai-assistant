### Findings and decisions

| # | Finding | Decision |
|---|---|---|
| F1 | **PostgreSQL 18 images reject a mount at `/var/lib/postgresql/data`** — data lives in a major-version subdirectory, so the mount belongs at `/var/lib/postgresql`. The db container exited 1 until this was changed. | `compose.dev.yml` mounts `db-data:/var/lib/postgresql`. ARCHITECTURE §14.2 already anticipates this for the production bind mount; **`compose.prod.yml` (M02 S02.5) must use the same mount point** and verify `PGDATA` on the pinned image at provisioning. |
| F2 | **`str(pydantic.ValidationError)` echoes the rejected input**, so rendering it would print `DATABASE_URL` complete with its password. | Every caller renders errors via `errors(include_input=False, include_url=False)`; `healthcheck` does. Pinned by `test_validation_errors_can_be_rendered_without_the_value` — a named regression test for the logging-hygiene invariant (AGENTS §9). |
| F3 | **gitleaks ≥ 8.19 removed `protect`**; the staged-changes scan is now `gitleaks git --staged <repo>`. Git Bash also rewrites container-side paths (`/repo` → `C:/Program Files/Git/repo`). | Hook pinned to `zricethezav/gitleaks:v8.30.1`, exports `MSYS_NO_PATHCONV=1`, and distinguishes a detection (exit 1) from gitleaks failing to run — an infrastructure failure must never be reported as a clean scan, nor as a detection (AGENTS §6.11). |
| F4 | An empty value in `.env` (`LLM_MONTHLY_BUDGET_USD=`) failed validation rather than meaning "unset" — `just healthcheck` caught it against the committed `.env.example`. | `_blank_means_unset` validator on every optional setting; `test_env_example_loads_as_valid_configuration` keeps `.env.example` a valid dev configuration. |
| F5 | The phone-number redaction pattern first drafted matched ISO dates and internal ids. | It now requires a leading `+` (the international form Telegram supplies). Over-redaction is pinned against by `test_identifiers_and_dates_are_not_over_redacted`. Bare-digit phone numbers rely on key-name dropping instead. |

## S00.3 Jobs spike — risk A6 and TQ-01 retired

Run 2026-10-17 against `pgvector/pgvector:pg18`, procrastinate 3.10.0,
SQLAlchemy 2.1.5, psycopg 3.3.6. Code and method: [`spikes/jobs/`](../../spikes/jobs/).
**8/8 checks passed.**

**Decision: procrastinate stays (ADR-06 Accepted). The hand-rolled queue
fallback is not needed, and neither is the "commit + defer + reconciler"
degradation — transactional defer works.**

| | Question | Result |
|---|---|---|
| E1 | Transactional defer on the session's raw psycopg connection (TQ-01) | **Works.** `job_manager.defer_job_async(job, connection=conn.driver_connection)`; rollback discards the domain row *and* the job, commit persists both. |
| E2 | Shared `lock` serializes execution | Yes, at `concurrency=4`. |
| E3 | `queueing_lock` dedupes | Yes — raises `AlreadyEnqueued`. |
| E4 | `schedule_in` honoured | Yes. |
| E5 | Future-scheduled **locked** job vs. a later immediate job with the same lock | **The immediate job is blocked.** The AGENTS §13 prohibition is confirmed by measurement, not inherited assumption. |
| E6 | `RetryStrategy` retries to success | Yes. |
| E7 | Alembic up/down/up with procrastinate's schema vendored as a revision | Yes. |

### Consequences for S01.1 / S01.5

- **F6 — Transactional defer is available**, so ARCHITECTURE §12.4's fallback
  path stays unused. S01.1 implements it as described in `spikes/jobs/README.md`.
- **F7 — procrastinate's schema downgrades generically.** Every object it
  creates is prefixed `procrastinate_`, so the Alembic revision drops them by
  prefix instead of naming ~40 objects. Re-vendor on every upgrade (AGENTS §12).
- **F8 — `App.with_connector()` returns a new app**; tasks registered on the
  original are not carried over. The composition root must build the `App` with
  its final connector (`bootstrap.py`, AGENTS §5).
- **F9 — a worker with `wait=False` cannot distinguish "blocked by a lock" from
  "queue empty".** Any S01.5 test that drains once will mis-read lock behaviour;
  drain until the expected jobs have run, against the fake clock.
