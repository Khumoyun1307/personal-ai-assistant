## S00.3 Jobs spike — risk A6 and TQ-01 retired

Run 2026-10-17 against `pgvector/pgvector:pg18`, procrastinate 3.10.0,
SQLAlchemy 2.1.5, psycopg 3.3.6. Code and method: [`spikes/jobs/`](../../spikes/jobs/).
**8/8 checks passed.**

**Decision: procrastinate stays (ADR-06 Accepted). The hand-rolled queue
fallback is not needed, and neither is the "commit + defer + reconciler"
degradation — transactional defer works.**

| | Question | Result |
|---|---|---|
| E1 | Transactional defer on the session's raw psycopg connection (TQ-01) | **Works.** `job_manager.defer_job_async(job, connection=conn.driver_connection)`; rollback discards the domain row *and* the job, commit persists both. |
| E2 | Shared `lock` serializes execution | Yes, at `concurrency=4`. |
| E3 | `queueing_lock` dedupes | Yes — raises `AlreadyEnqueued`. |
| E4 | `schedule_in` honoured | Yes. |
| E5 | Future-scheduled **locked** job vs. a later immediate job with the same lock | **The immediate job is blocked.** The AGENTS §13 prohibition is confirmed by measurement, not inherited assumption. |
| E6 | `RetryStrategy` retries to success | Yes. |
| E7 | Alembic up/down/up with procrastinate's schema vendored as a revision | Yes. |

### Consequences for S01.1 / S01.5

- **F6 — Transactional defer is available**, so ARCHITECTURE §12.4's fallback
  path stays unused. S01.1 implements it as described in `spikes/jobs/README.md`.
- **F7 — procrastinate's schema downgrades generically.** Every object it
  creates is prefixed `procrastinate_`, so the Alembic revision drops them by
  prefix instead of naming ~40 objects. Re-vendor on every upgrade (AGENTS §12).
- **F8 — `App.with_connector()` returns a new app**; tasks registered on the
  original are not carried over. The composition root must build the `App` with
  its final connector (`bootstrap.py`, AGENTS §5).
- **F9 — a worker with `wait=False` cannot distinguish "blocked by a lock" from
  "queue empty".** Any S01.5 test that drains once will mis-read lock behaviour;
  drain until the expected jobs have run, against the fake clock.

## S00.3 Search spike — ADR-10 validated

Run 2026-10-17 against `pgvector/pgvector:pg18`. Code and method:
[`spikes/search/`](../../spikes/search/). **6/6 checks passed.** All samples
hand-written and synthetic.

**Decision: ADR-10 holds — no vector database for Personal v1.** Cross-script
retrieval is solved by one normalization function plus `tsvector` + `pg_trgm`.

| | Question | Result |
|---|---|---|
| S1 | Do 1995 Latin, new Latin, backtick Latin and Uzbek Cyrillic converge? | **Yes**, on one key: `özbekiston respublikasi ğalaba qozondi`. |
| S2 | Does a query in any script retrieve text stored in any other? | **Yes**, all five query spellings returned all three Uzbek rows. `ts_debug` shows `özbekiston`/`ğalaba` tokenised whole. |
| S3 | Does `pg_trgm` help with an apostrophe-less typo? | Yes — the Uzbek rows rank first for `galaba`. |
| S4 | Do Russian and English survive the pipeline? | Yes; Russian transliterates consistently on both sides and stays retrievable. |

**F10 — `pg_trgm` hashes multibyte trigrams.** `show_trgm('ğalaba')` returns
hashes (`0x9e987f`, …) for the trigrams containing `ğ`, not literal trigrams.
Fuzzy matching worked, but similarity around the canonical `ö`/`ğ` is hash-based
and scores lower than for ASCII. This is an input to the **S03.4 retrieval
thresholds**, not a reason to change ARCHITECTURE §11.2 now; if Uzbek fuzzy
recall falls short there, the alternatives to measure are an ASCII-only
canonical form (losing the vowel distinction) or query-variant generation. The
decision is the owner's at M03 (AGENTS §2).

## Provider changed to OpenAI (owner decision, 2026-10-18)

The owner switched the LLM provider from Anthropic to OpenAI on cost grounds,
with `gpt-6-luna` as the default model and a **$5/month** budget. Recorded as
**ADR-07a** (ARCHITECTURE §20); the original ADR-07 is marked superseded rather
than rewritten, since it was never implemented.

The `LLMClient` port was designed provider-neutral for exactly this, so the swap
is an adapter change, not a rewrite. No LLM code existed yet, so nothing had to
be unwound.

**Changed:** `pyproject.toml` (`anthropic` → `openai` 3.35.1), `config.py`
(`OPENAI_API_KEY`, default `gpt-6-luna`), `.env.example`, the secret-redaction
pattern and `CHATTY_LOGGERS`, the import-linter contract (domain packages now
may not import `openai`), AGENTS §1/§8/§14, ARCHITECTURE §3/§5/§7.4/§14.3/§15.2/
§17/§18/§20/§21, TF PQ-05/PQ-06/PQ-09.

### Two consequences worth stating plainly

- **F11 — the cost strategy is inverted.** The design assumed starting on a
  capable model and lowering `effort`, with a *downgrade* allowed only after
  evaluation. `gpt-6-luna` is the cheapest tier ($0.10/$0.50 per 1M tokens),
  so there is nothing below it. Budget risk is now low; **quality risk is high**,
  and the Uzbek evaluation (A8/A9, PQ-05) becomes the gate that decides whether
  routes must move **up** to `gpt-6-sol`/`gpt-6-astra`. ARCHITECTURE §7.4 was
  rewritten accordingly.
- **F12 — provider terms are unverified, and this blocks the live spike.**
  TF §7.2 still records Anthropic's retention/no-training terms. Training on API
  data is disabled in the owner's account, but AGENTS §9 requires the processor's
  terms recorded and the consent text and privacy policy naming OpenAI **before
  any message content is sent**. Tracked as **PQ-09**; it blocks S00.3 going live.

At $0.10/$0.50 per 1M tokens the $5/month budget looks workable for modest
volume, but no estimate should be trusted until Uzbek token inflation is
measured (TQ-03) — both Uzbek scripts tokenize worse than English.

## S00.2 Telegram probe and live validation

**Harness written and committed; LV sessions run 2026-10-18 (results below and in TF §12).**

[`tools/probe/`](../../tools/probe/) is ready: a long-poller that writes raw
updates to the git-ignored `var/probe/`, plus the command set that covers every
LV row (see the table in its README). It obeys the same rules as the
application — an explicit `allowed_updates` list, never
`drop_pending_updates=True`, and full payloads only for allow-listed chat ids.
Every API call records its exact error class, message and `retry_after`, which
is the actual deliverable for LV-04, LV-08 and LV-16.

[`tools/probe/sanitize.py`](../../tools/probe/sanitize.py) turns a dump into
committable fixtures. It is default-deny for strings, remaps identifiers
consistently, and preserves UTF-16 length so message entity offsets stay valid.
Its contract is pinned by `tests/unit/test_probe_sanitizer.py` (8 tests),
including that an unknown future field never passes through.
