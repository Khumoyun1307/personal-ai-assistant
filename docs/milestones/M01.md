## S01.1 Data foundation

**Delivered:** Alembic (async env, `app` schema) with two reviewed revisions —
the ten baseline tables and procrastinate's schema vendored into its own
schema; SQLAlchemy 2.1 typed models; engine/session factory; unit of work;
`AccountScopedRepository`; the `Clock` port with `SystemClock` and `FakeClock`;
`python -m assistant migrate`.

**Verified:** `just check` exit 0 — ruff, ruff format, `mypy --strict` (34
files), 4 import contracts, **92 tests** (20 new). `just migrate` and
`just healthcheck` exit 0 against the dev database. Migrations applied,
reversed to base and re-applied against a throwaway database in an automated
test, not by hand.

### Design decisions

| # | Decision | Why |
|---|---|---|
| D1 | `AccountScopedRepository` takes `account_id` in its **constructor**, and `get()` takes only an entity id | Forgetting the tenant filter is not expressible. `get()` returns `None` for another account's row — indistinguishable from "missing", which is the point. `add()` overwrites `account_id`, so a wrongly-built object cannot be smuggled in. `account_id <= 0` raises rather than meaning "all accounts". |
| D2 | `inbound_updates.account_id` is **nullable** — a deliberate exception to AGENTS §6.12 | An update arrives before we know whose it is, and updates from non-allowlisted senders never get one (§6 invariant 12). The exception is named explicitly in the test that asserts every other tenant table has the column. |
| D3 | Enums as `text` + `CHECK` | Adding a value is a one-line migration instead of a PostgreSQL enum rewrite (ARCHITECTURE §10.1). |
| D4 | `bigint generated always as identity` | A client cannot supply its own id and collide with the generator; pinned by a test that expects `GeneratedAlways` on an explicit insert. |
| D5 | procrastinate's schema applied with `SET LOCAL search_path` | Its SQL is schema-unqualified. A test asserts its tables land in `procrastinate` and **not** in `public`, because that regression would be silent and would differ per environment. |

### Findings

| # | Finding |
|---|---|
| F13 | **A missing `await connection.commit()` in the async Alembic env made every migration a silent no-op** — SQLAlchemy 2.x opens an implicit transaction on `connect()`, so the whole run was rolled back on close while `alembic upgrade head` still exited **0**. Caught only by checking the database afterwards. Anything that trusts alembic's exit code alone would have reported success forever. |
| F14 | Revision 0001 originally dropped the `app` schema on downgrade, which deleted alembic's own `version` table mid-downgrade and failed the reversal. The schema is env-level bootstrap (env.py creates it before the first revision runs), so 0001 now drops only its tables. |
| F15 | A column named `text` on `ControlTurn` shadowed `sqlalchemy.text` inside the class body (`TypeError: 'MappedColumn' object is not callable`). The import is aliased `sql_text`. Worth remembering for `messages.text` in M02. |
| F16 | The generic bound `Base` cannot also promise an `account_id` column, so the repository's scoping was untypeable under `mypy --strict`. Resolved with an explicit `TenantOwned` protocol the casts are checked against, rather than scattering `Any`. |

### Not done in this slice

- Repositories for each table (added per slice as they are needed).
- `conversations`, `contacts`, `messages` and everything M02 — out of M01 scope.

## S01.2 Durable ingestion

**Delivered:** the durable poller (offset advanced only after commit, explicit
`allowed_updates`, startup checks, bot-identity guard, 409 handling, heartbeat);
the inbox writer (`ON CONFLICT DO NOTHING`); the routing table; the inbox
processor (ordered claim with `FOR UPDATE SKIP LOCKED`, per-row transactions,
transient-vs-deterministic error classes, 3-attempt dead-letter); `AdvisoryLock`
for singleton enforcement; Telegram error classification;
`python -m assistant inbox requeue|status`; `FakeUpdateSource`.

**Verified:** `just check` exit 0 — ruff, format, `mypy --strict` (43 files),
4 import contracts, **132 tests** (40 new).

### What the tests actually prove

Not that the code runs, but the claims the design rests on:

- **A crash before commit loses nothing.** The test writes a batch, rolls it
  back to stand in for a crash, asserts the rows are gone, replays the same
  batch, and asserts everything lands exactly once.
- **The offset advances only after the batch commits**, and the first call
  omits the offset entirely so Telegram replays its oldest unconfirmed update.
- **A poison row does not block the queue behind it** — dead-lettered after 3
  attempts while the next row still processes.
- **A transient error does not burn an attempt**, so a Telegram outage cannot
  dead-letter the backlog.
- **Non-owner payloads are cleared in the same transaction** that rejects the
  row (invariant 12).
- **Business updates never route to control**, including when `from.id` is the
  owner (invariant 5) — a business message from the owner is something they
  typed to a *contact*, not an instruction.
- **An empty allowlist refuses everyone** rather than opening the control chat.

### Design decisions

| # | Decision | Why |
|---|---|---|
| D6 | Routing **vocabulary** (`Route`, `RouteDecision`) in `core/`; the Telegram **parser** in `telegram/routing.py`; the processor takes a `Router` callable | The first attempt put both in `telegram/` and broke the layer contract: `inbox` is a domain package and may not import an adapter. The split is the architecture working, not a workaround. |
| D7 | Updates cross the ingress port as plain dicts, not aiogram models | The raw payload is what gets stored anyway, and an aiogram upgrade then cannot change ingestion semantics silently. |
| D8 | The advisory lock folds namespace and key into **one bigint** | `pg_try_advisory_lock(int, int)` takes int4 and a Telegram bot id does not fit. |
| D9 | The non-owner **refusal send** is deferred to S01.3 | It must go through `OutboundGateway` (AGENTS §17), which lands in S01.3. Until then the update is classified, marked `rejected` and its payload cleared — the safe half. A second send path would violate the confinement rule. |

### Findings

| # | Finding |
|---|---|
| F17 | **`pg_try_advisory_lock(int, int)` cannot take a Telegram bot id** — the two-argument form is int4 and bot ids exceed it. Folded into the single bigint form. Found by a test, not by reading docs. |
| F18 | Putting the routing table in `telegram/` made the domain import an adapter. import-linter caught it at the gate — the contract earned its keep on the first slice that could break it. |

### Not done in this slice

- The fixed refusal **reply** (D9) — S01.3, with the gateway.
- The `/pause` fast lane in the poller (§6.1): needs the control-chat command.
- Wiring poller and processor into a running process — that is S01.5 (roles,
  supervisor). `just run` still exits 2 by design.

## S01.3 Control chat basics

**Delivered:** `OutboundGateway` (typed targets, per-chat throttling, error
classification); the HTML sanitiser/splitter; callback tokens; account, consent
and pending-input services; the control dispatcher with `/start`, `/help`,
`/status`, `/settings`, `/privacy`, `/pause`, `/resume`, stop words and free
text; privacy policy **v0 draft**; the AST test banning aiogram shortcuts.

**Verified:** `just check` exit 0 — ruff, format, `mypy --strict` (49 files),
4 import contracts, **241 tests** (109 new).

### What the tests actually prove

- **No AI call without consent** — `require_consent` raises rather than
  returning a flag, and it raises again if the consent does not name the
  processor being used. Switching provider without re-asking is exactly the
  case that catches.
- **Onboarding survives a restart** — the question the bot asked lives in
  `pending_inputs`, not in process memory.
- **A `/command` always beats a pending question**, so an owner who changes
  their mind does not have `/status` swallowed as an answer.
- **The kill switch never touches the model** — stop words are matched
  deterministically, in all four languages the owner uses, so pausing works
  when the provider is down or out of budget. A sentence *containing* "stop"
  does not trip it.
- **No control-chat send ever carries a `business_connection_id`**, asserted
  across every flow in the suite.
- **`chat not found` is not reported as a block** (TF §12 LV-09).
- **Unsupported HTML is escaped, not stripped** — stripping would silently
  change what a message said.

### Design decisions

| # | Decision | Why |
|---|---|---|
| D10 | `OutboundGateway.send_text` **raises** on a `BusinessChat` target | §6 invariant 1: nothing may send on the owner's behalf without passing policy, and the policy engine arrives in M04. The target type exists so the shape is right; reaching it is a programming error, not a runtime branch. |
| D11 | Handlers are plain functions over our own `IncomingMessage`, not aiogram models | They are testable without constructing Telegram objects, and they cannot accidentally reach an aiogram shortcut that would send as the owner. |
| D12 | Routing precedence: command → stop word → pending input → free text | Each ordering is a failure avoided: a command swallowed as an answer; a kill switch that needs the model; a multi-step flow that cannot survive a restart. |
| D13 | `allowed-confusables` configured for Uzbek orthography | `oʻ`/`gʻ` are correct Uzbek characters, not typos. Without this every Uzbek string in the product trips ruff's ambiguous-character rule, training everyone to add noqa. |

### Findings

| # | Finding |
|---|---|
| F19 | `consents.processors` was typed as a JSON **object** but holds an **array** of processor names. Caught by `mypy --strict` as an unreachable branch, before any data existed to migrate. |

### Not done in this slice

- **The privacy policy is a draft and is not published.** Four things must
  happen first (listed at the end of the policy): PQ-09 (OpenAI's retention
  terms recorded), the owner choosing a host and contact address, owner
  approval of the text, and registering the URL with @BotFather. Until then no
  message content may reach a provider.
- Inline keyboards and the generic confirmation card: no flow needs buttons
  until approval cards exist (M04). The token layer they will use is built and
  tested.
- Deep links (`/start bizChat<id>`) — they address a conversation, which does
  not exist until M02.
- Wiring the dispatcher into the inbox processor's CONTROL route: S01.5, with
  the running process.

## S01.4 Agent runtime v1

**Delivered:** the `LLMClient` port (`llm/port.py`, provider-neutral types with
per-item provenance); the OpenAI adapter (`llm/openai_adapter.py`, Responses
API); the consent choke point (`llm/consent.py`) and metering
(`llm/metering.py`, the single price table); `FakeLLM` (`tests/fakes/llm.py`);
the owned agent loop (`agent/runtime.py`) with the `owner_request` context
builder, versioned prompt `owner_request.v1`, and run/turn/`llm_calls`
persistence; the tool registry and executor with one tool, `get_status` (flag
`tool.get_status`, default off); the `ControlChannel` port and its Telegram
adapter (`telegram/control/agent_channel.py`); `bootstrap.build_llm_client` /
`build_owner_runtime`; settings `LLM_OWNER_REQUEST_EFFORT` and `FEATURE_FLAGS`.

**Checks:** `ruff`, `ruff format`, `mypy --strict src` (62 files), 4
import-linter contracts kept (the agent contract now also forbids `openai`, the
OpenAI adapter and `bootstrap`), full test suite green: 335 collected, 1
pre-existing skip. New: 59 unit tests, 16 integration tests against the Compose
Postgres.

### What the tests actually prove

- **`store=False` on every request** (TF §7.2), across plain, tool, effort and
  replay requests, and on the actual SDK call. `previous_response_id`,
  `conversation` and `background` are never sent.
- **No model call without consent** (§6 invariant 9): the consent wrapper raises
  before the inner client is called (FakeLLM records zero requests) for missing
  `ai_control`, for managed content without `ai_managed`, and for a consent
  that does not name `OpenAI`. Consent is read on every call. The runtime also
  checks first, so the owner gets a plain message and no run row is written.
- **RG-17:** contact-triggered run types get no tools even with every flag on;
  no registered tool can send, edit, delete or mark read, and such a tool cannot
  be registered at all; tools cannot be granted to non-`owner_request` runs.
- **The loop terminates** on iterations, the token budget and the wall-clock
  deadline (FakeClock, no sleeps).
- **Tool round trip:** the model's own output is appended unchanged, then all
  results of that turn; a repeated `call_id` executes once; schema-invalid
  arguments are reported by field without echoing input; a foreign-account id
  reads as "not found"; steps are content-free (digest only).
- **Honest failure:** refusal → safe reply; provider outage → "cannot reach the
  provider" and no crash; truncation → one retry with double the budget; an
  undelivered reply is recorded as such; a reached monthly budget means no call.
- **Metering:** every successful call writes an `llm_calls` row with tokens and
  cost (`0.000080` USD for 300 in / 100 out on Luna).
- Managed control turns are excluded from context without `ai_managed`, and a
  reply built from managed content is itself flagged `contains_managed`.

### Provider calls verified (AGENTS §8)

Checked against the installed `openai` 3.35.1 package and the official docs on
2026-10-18, not assumed: `AsyncOpenAI.responses.create` / `.parse(text_format=…)`
signatures; `store` "defaults to true when omitted" (SDK docstring);
`include=["reasoning.encrypted_content"]` for stateless multi-turn with
reasoning (SDK docstring); `function_call_output` items and replaying
`response.output` in `input` (function-calling guide); strict tool schemas need
`additionalProperties: false` and every property required (same guide);
`Response.status` / `incomplete_details.reason`; refusal content parts;
`ResponseUsage.input_tokens_details.cached_tokens`; `_request_id`; SDK
exception classes (transport is `httpx2`, added to the prod debug-logger guard).

### Design decisions

| # | Decision | Why |
|---|---|---|
| D14 | Consent gate outermost, metering inside it, adapter innermost | A call without consent must not reach any layer that could act on it. Metering in a wrapper means a new run type cannot forget it. |
| D15 | Stateless Responses API (`store=false`) with encrypted reasoning replayed within a run; never `previous_response_id` | `previous_response_id` only works with stored responses, which would keep owner text at OpenAI for 30 days (TF §7.2). |
| D16 | Provenance on every request item, not a per-request flag | The consent wrapper decides from the items themselves whether managed content is present, so a tool result carrying contact text cannot slip past by being added late in a run. |
| D17 | Runtime as a callable service (`run(turn_id)`) behind a `ControlChannel` port | The agent may not import `telegram/`; the job that calls it (`agent.owner_request`) is S01.5. |
| D18 | Cached input tokens charged at the full input price | The cached-token discount is not verified; over-estimating keeps the monthly budget check on the safe side. |
| D19 | Run-level idempotency is per `call_id` in memory; no new column | Read tools are harmless to repeat. Persisted idempotency matters for `propose_*` tools, keyed by `(run_id, tool_call_id)` on `actions` (M04). |

### Findings

| # | Finding |
|---|---|
| F20 | The OpenAI SDK 3.x transport is `httpx2`, not `httpx`; it logs under its own name, so the production debug-logger guard did not cover it. Fixed. |
| F21 | `responses.parse` parses inside the SDK call, so truncated JSON raises `pydantic.ValidationError` before any status can be checked. Mapped to `INVALID_OUTPUT`: invalid output never triggers anything. |
| F22 | The API reports the resolved model, possibly with a snapshot suffix; price lookup matches the configured name as a prefix. |

### Not done in this slice

- **Unverified until the first live call:** whether `gpt-6-luna` accepts
  `reasoning.effort` — default changed from `medium` to **`low`** by the owner on
  2026-10-18 (light reasoning for cost); set `LLM_OWNER_REQUEST_EFFORT=` empty
  if the model rejects the parameter —
  the real token usage for Uzbek text (TQ-03), and that the configured model id
  resolves. No live call was made: it needs the owner's go-ahead, and real owner
  text needs the privacy policy published first (S01.3 "Not done").
- Wiring into the running process (`agent.owner_request` job, dispatcher →
  turn → job), the typing-latency measurement and the manual acceptance tests:
  S01.5.
- Budget soft alerts at 50/80 % (`notify_owner`): S01.5. The hard stop at
  100 % is in.
- Taint detection for forwarded/quoted owner text (RG-11): S03.1, when the
  first tool returning contact text exists. The `tainted` column is written as

- The budget month is the UTC calendar month, not the owner's timezone.

## S01.5 Jobs and system tasks

**Delivered:** procrastinate wired for real — `jobs/app.py` (queues `system` 1,
`outbound` 2, `llm` 3, one worker each), `jobs/scheduler.py` (the
`JobScheduler` port, with transactional defer), `jobs/tasks.py` (the M01 task
catalogue), `jobs/reconcile.py`; the in-process supervisor
(`core/supervisor.py`) and roles (`process.py`); `bootstrap.running_process`
and `python -m assistant run [--roles=…]`; `notify_owner`
(`inbox/notify.py`) behind every system alert; the ingestion watchdog
(`inbox/watchdog.py`), the 7-day payload sweep (`privacy/retention.py`), budget
alerts (`agent/budget.py`) and the external heartbeat ping
(`observability/heartbeat.py`); `AiogramSender` in the gateway; the inbox
CONTROL/REFUSED handlers (`telegram/control/inbox_handlers.py`), which finally
connect the S01.3 dispatcher to the running inbox. Free text now becomes a turn
**and** an `agent.owner_request` job in one transaction.

**Checks:** ruff, ruff format, `mypy --strict src` (76 files), 4 import
contracts kept, full suite green: 386 collected, 1 pre-existing skip. New: 14
unit tests, 23 integration tests (real Postgres and real procrastinate
workers). No live Telegram or OpenAI call was made.

### What the tests actually prove

- **Owner turns run one at a time per account, in order**, with the `llm`
  worker at concurrency 3 — only the `acct:{id}:control` lock serializes them.
- **A slow agent run does not delay `system` or `outbound` jobs**: while an
  `llm` job is held open, a system job and an outbound job both complete.
- **Stalled-job recovery:** a job left `doing` by a worker with a 10-minute-old
  heartbeat is put back to `todo` by `system.retry_stalled_jobs`.
- **Transactional defer, for real:** a free-text turn and its job commit
  together; a crash before commit leaves neither.
- **The reconciler** re-defers only a lost turn between 30 s and 1 h old, and is
  idempotent. A lock on a future-scheduled job is refused (AGENTS §13).
- **No double answers:** a re-delivered job for an answered turn is a no-op; a
  run cut off mid-way is marked `interrupted` and the turn is answered once.
- **Supervisor:** any role ending (crash *or* return) exits non-zero, for each of
  poller / inbox / worker:system / worker:llm; an unhealthy probe exits non-zero;
  a real SIGTERM during an in-flight control-chat send lets it finish, then
  exits 0; a role ignoring `stop()` is cancelled after its grace period.
- **Watchdog:** a stale poller heartbeat alerts once per hour, a fresh one never;
  each dead-lettered row alerts once; an undelivered alert is retried.
- **Retention:** payloads older than 7 days are cleared, except rows still
  pending.
- **Budget:** 50/80/100 % each alert once per month; a new month starts over.
- **Inbox wiring:** owner commands are answered without a
  `business_connection_id`; a stranger gets one refusal per window, no account,
  no turn, payload cleared; a button press is always answered; an owner
  `business_message` reading `/help` never reaches the control chat (RG-03).
- **The assembled process** (synthetic token, no network) starts its workers,
  registers them with procrastinate, stops cleanly with exit 0 and unregisters;
  a second inbox processor refuses to start.

### Design decisions

| # | Decision | Why |
|---|---|---|
| D20 | Task bodies on a plain `JobHandlers` class; procrastinate wrappers are thin closures registered on the final app | Testable without a worker, no module globals, and no `with_connector()` trap (M00 F8). |
| D21 | `ControlChannel` and `JobScheduler` ports live in `core/` | The domain alert service, the agent and the dispatcher all need them and none may import an adapter. |
| D22 | Reconciler keys on procrastinate job status, not on `agent_runs` | A turn skipped for missing consent has no run row by design; keying on runs would re-send the consent message every minute. |
| D23 | Dead-letter alerts come from the watchdog, not from the processor | One path for alerts, no coupling of the inbox to Telegram sends, and the dedupe key (`dead_letter:{row}`) makes it once-per-row. |
| D24 | Refusal rate limiting in memory (per chat 1/h, global 20/10 min), chat ids hashed | The people refused are not tenants; a durable record of them is the trace §6 invariant 12 forbids. A restart resetting the window is acceptable for a courtesy reply. |
| D25 | Heartbeat ping via stdlib `urllib` in a thread, http(s) only | No new dependency; the scheme guard keeps `urllib` off `file://`. |
| D26 | Control command replies stay inside the inbox row's transaction | Matches the S01.3 handler design; the cost is a possible repeated *command* reply after a crash between send and commit. Agent answers are jobs and are protected by D22 and the run idempotency check. |

### Findings

| # | Finding |
|---|---|
| F23 | The stop-word reply told the owner to "say resume", but AGENTS §6 allows resuming only via `/resume` or a card. Corrected to "/resume". |
| F24 | Each procrastinate worker runs its own periodic deferrer; three workers in one process are safe because procrastinate deduplicates periodic defers in `procrastinate_periodic_defers`. |
| F25 | `get_stalled_jobs` needs the same `seconds_since_heartbeat` as the worker's `stalled_worker_timeout` (60 s here), or it would treat busy workers as dead. |
