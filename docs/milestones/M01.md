## S01.1 Data foundation

**Delivered:** Alembic (async env, `app` schema) with two reviewed revisions —
the ten baseline tables and procrastinate's schema vendored into its own
schema; SQLAlchemy 2.1 typed models; engine/session factory; unit of work;
`AccountScopedRepository`; the `Clock` port with `SystemClock` and `FakeClock`;
`python -m assistant migrate`.

**Verified:** `just check` exit 0 — ruff, ruff format, `mypy --strict` (34
files), 4 import contracts, **92 tests** (20 new). `just migrate` and
`just healthcheck` exit 0 against the dev database. Migrations applied,
reversed to base and re-applied against a throwaway database in an automated
test, not by hand.

### Design decisions

| # | Decision | Why |
|---|---|---|
| D1 | `AccountScopedRepository` takes `account_id` in its **constructor**, and `get()` takes only an entity id | Forgetting the tenant filter is not expressible. `get()` returns `None` for another account's row — indistinguishable from "missing", which is the point. `add()` overwrites `account_id`, so a wrongly-built object cannot be smuggled in. `account_id <= 0` raises rather than meaning "all accounts". |
| D2 | `inbound_updates.account_id` is **nullable** — a deliberate exception to AGENTS §6.12 | An update arrives before we know whose it is, and updates from non-allowlisted senders never get one (§6 invariant 12). The exception is named explicitly in the test that asserts every other tenant table has the column. |
| D3 | Enums as `text` + `CHECK` | Adding a value is a one-line migration instead of a PostgreSQL enum rewrite (ARCHITECTURE §10.1). |
| D4 | `bigint generated always as identity` | A client cannot supply its own id and collide with the generator; pinned by a test that expects `GeneratedAlways` on an explicit insert. |
| D5 | procrastinate's schema applied with `SET LOCAL search_path` | Its SQL is schema-unqualified. A test asserts its tables land in `procrastinate` and **not** in `public`, because that regression would be silent and would differ per environment. |

### Findings

| # | Finding |
|---|---|
| F13 | **A missing `await connection.commit()` in the async Alembic env made every migration a silent no-op** — SQLAlchemy 2.x opens an implicit transaction on `connect()`, so the whole run was rolled back on close while `alembic upgrade head` still exited **0**. Caught only by checking the database afterwards. Anything that trusts alembic's exit code alone would have reported success forever. |
| F14 | Revision 0001 originally dropped the `app` schema on downgrade, which deleted alembic's own `version` table mid-downgrade and failed the reversal. The schema is env-level bootstrap (env.py creates it before the first revision runs), so 0001 now drops only its tables. |
| F15 | A column named `text` on `ControlTurn` shadowed `sqlalchemy.text` inside the class body (`TypeError: 'MappedColumn' object is not callable`). The import is aliased `sql_text`. Worth remembering for `messages.text` in M02. |
| F16 | The generic bound `Base` cannot also promise an `account_id` column, so the repository's scoping was untypeable under `mypy --strict`. Resolved with an explicit `TenantOwned` protocol the casts are checked against, rather than scattering `Any`. |

### Not done in this slice

- Repositories for each table (added per slice as they are needed).
- `conversations`, `contacts`, `messages` and everything M02 — out of M01 scope.

## S01.2 Durable ingestion

**Delivered:** the durable poller (offset advanced only after commit, explicit
`allowed_updates`, startup checks, bot-identity guard, 409 handling, heartbeat);
the inbox writer (`ON CONFLICT DO NOTHING`); the routing table; the inbox
processor (ordered claim with `FOR UPDATE SKIP LOCKED`, per-row transactions,
transient-vs-deterministic error classes, 3-attempt dead-letter); `AdvisoryLock`
for singleton enforcement; Telegram error classification;
`python -m assistant inbox requeue|status`; `FakeUpdateSource`.

**Verified:** `just check` exit 0 — ruff, format, `mypy --strict` (43 files),
4 import contracts, **132 tests** (40 new).

### What the tests actually prove

Not that the code runs, but the claims the design rests on:

- **A crash before commit loses nothing.** The test writes a batch, rolls it
  back to stand in for a crash, asserts the rows are gone, replays the same
  batch, and asserts everything lands exactly once.
- **The offset advances only after the batch commits**, and the first call
  omits the offset entirely so Telegram replays its oldest unconfirmed update.
- **A poison row does not block the queue behind it** — dead-lettered after 3
  attempts while the next row still processes.
- **A transient error does not burn an attempt**, so a Telegram outage cannot
  dead-letter the backlog.
- **Non-owner payloads are cleared in the same transaction** that rejects the
  row (invariant 12).
- **Business updates never route to control**, including when `from.id` is the
  owner (invariant 5) — a business message from the owner is something they
  typed to a *contact*, not an instruction.
- **An empty allowlist refuses everyone** rather than opening the control chat.

### Design decisions

| # | Decision | Why |
|---|---|---|
| D6 | Routing **vocabulary** (`Route`, `RouteDecision`) in `core/`; the Telegram **parser** in `telegram/routing.py`; the processor takes a `Router` callable | The first attempt put both in `telegram/` and broke the layer contract: `inbox` is a domain package and may not import an adapter. The split is the architecture working, not a workaround. |
| D7 | Updates cross the ingress port as plain dicts, not aiogram models | The raw payload is what gets stored anyway, and an aiogram upgrade then cannot change ingestion semantics silently. |
| D8 | The advisory lock folds namespace and key into **one bigint** | `pg_try_advisory_lock(int, int)` takes int4 and a Telegram bot id does not fit. |
| D9 | The non-owner **refusal send** is deferred to S01.3 | It must go through `OutboundGateway` (AGENTS §17), which lands in S01.3. Until then the update is classified, marked `rejected` and its payload cleared — the safe half. A second send path would violate the confinement rule. |

### Findings

| # | Finding |
|---|---|
| F17 | **`pg_try_advisory_lock(int, int)` cannot take a Telegram bot id** — the two-argument form is int4 and bot ids exceed it. Folded into the single bigint form. Found by a test, not by reading docs. |
| F18 | Putting the routing table in `telegram/` made the domain import an adapter. import-linter caught it at the gate — the contract earned its keep on the first slice that could break it. |

### Not done in this slice

- The fixed refusal **reply** (D9) — S01.3, with the gateway.
- The `/pause` fast lane in the poller (§6.1): needs the control-chat command.
- Wiring poller and processor into a running process — that is S01.5 (roles,
  supervisor). `just run` still exits 2 by design.

## S01.3 Control chat basics

**Delivered:** `OutboundGateway` (typed targets, per-chat throttling, error
classification); the HTML sanitiser/splitter; callback tokens; account, consent
and pending-input services; the control dispatcher with `/start`, `/help`,
`/status`, `/settings`, `/privacy`, `/pause`, `/resume`, stop words and free
text; privacy policy **v0 draft**; the AST test banning aiogram shortcuts.

**Verified:** `just check` exit 0 — ruff, format, `mypy --strict` (49 files),
4 import contracts, **241 tests** (109 new).

### What the tests actually prove

- **No AI call without consent** — `require_consent` raises rather than
  returning a flag, and it raises again if the consent does not name the
  processor being used. Switching provider without re-asking is exactly the
  case that catches.
- **Onboarding survives a restart** — the question the bot asked lives in
  `pending_inputs`, not in process memory.
- **A `/command` always beats a pending question**, so an owner who changes
  their mind does not have `/status` swallowed as an answer.
- **The kill switch never touches the model** — stop words are matched
  deterministically, in all four languages the owner uses, so pausing works
  when the provider is down or out of budget. A sentence *containing* "stop"
  does not trip it.
- **No control-chat send ever carries a `business_connection_id`**, asserted
  across every flow in the suite.
- **`chat not found` is not reported as a block** (TF §12 LV-09).
- **Unsupported HTML is escaped, not stripped** — stripping would silently
  change what a message said.

### Design decisions

| # | Decision | Why |
|---|---|---|
| D10 | `OutboundGateway.send_text` **raises** on a `BusinessChat` target | §6 invariant 1: nothing may send on the owner's behalf without passing policy, and the policy engine arrives in M04. The target type exists so the shape is right; reaching it is a programming error, not a runtime branch. |
| D11 | Handlers are plain functions over our own `IncomingMessage`, not aiogram models | They are testable without constructing Telegram objects, and they cannot accidentally reach an aiogram shortcut that would send as the owner. |
| D12 | Routing precedence: command → stop word → pending input → free text | Each ordering is a failure avoided: a command swallowed as an answer; a kill switch that needs the model; a multi-step flow that cannot survive a restart. |
| D13 | `allowed-confusables` configured for Uzbek orthography | `oʻ`/`gʻ` are correct Uzbek characters, not typos. Without this every Uzbek string in the product trips ruff's ambiguous-character rule, training everyone to add noqa. |

### Findings

| # | Finding |
|---|---|
| F19 | `consents.processors` was typed as a JSON **object** but holds an **array** of processor names. Caught by `mypy --strict` as an unreachable branch, before any data existed to migrate. |

### Not done in this slice

- **The privacy policy is a draft and is not published.** Four things must
  happen first (listed at the end of the policy): PQ-09 (OpenAI's retention
  terms recorded), the owner choosing a host and contact address, owner
  approval of the text, and registering the URL with @BotFather. Until then no
  message content may reach a provider.
- Inline keyboards and the generic confirmation card: no flow needs buttons
  until approval cards exist (M04). The token layer they will use is built and
  tested.
- Deep links (`/start bizChat<id>`) — they address a conversation, which does
  not exist until M02.
- Wiring the dispatcher into the inbox processor's CONTROL route: S01.5, with
  the running process.
